# 思维层治理

> 2026-06-03 启用。与代码层治理（REQ ID、changelog、import 隔离）并行。

## 为什么需要

代码层治理管不住"AI 接到任务直接行动"的问题。
- 收到"排查下 CI/CD" → 直接调 git log、curl、vercel env
- 没有目标 → 没有路径 → 行动漂移
- 知道但做不到,是因为缺**思维层**的强制机制

本文件定义思维层治理,弥补这个缺口。

## 强制三件套

每个任务开始前,AI 必须输出:

1. **【目标】** 要达成什么（可验证,不是描述过程）
2. **【路径】** 分几步 + 每步的输入 / 输出 / 验证命令
3. **【风险】** 哪些步骤会破坏现有状态,如何回滚

未输出或用户未确认前,**不调任何工具**。

例外: 单行 typo 修复、明确的小改可不输出,但需在内心自问。

## 决策矩阵

| 情况 | 做法 |
|------|------|
| 缺目标 | **必须补,不能调研** |
| 缺范围 | **必须补,不能调研** |
| 缺接口 | 可以调研竞品 |
| 缺依赖 | 可以调研技术方案 |
| 缺验收 | **必须补,不能调研** |

**核心原则:** 调研不能替代决策。调研是为了补全设计依据,不是为了逃避决策。

## 持久化位置（四层兜底）

| 层 | 文件 | 跨会话 | 强度 |
|---|------|--------|------|
| **Memory**（最高优先） | `~/.claude/projects/-Users-nsss-Price-v3/memory/feedback_*.md` | ✓ | 强 |
| **行为准则**（项目级） | `governance/ai-behavior-准则/cursorrules` | ✓ | 强 |
| **治理真相**（文档级） | 本文件 | ✓ | 中 |
| **Hook**（工具调用前） | `.claude/settings.json` → `claude-user-prompt-submit.js` | ✓ | 提示 |

为什么不用 hooks 强制阻断?
- hooks 是"代码层治理",管不了"AI 不知道要输出"
- 加 hook 增加维护成本,Memory + 行为准则已经覆盖
- 在 `claude-user-prompt-submit.js` 顶部加注释提示,作为最后一道提醒

## 维护规则

1. **决策矩阵是 SoT** —— 改它必须同时更新所有层（Memory / cursorrules / 本文件）
2. **append-only** —— 新增"思维规则"追加,不准覆盖旧的
3. **可演进** —— 矩阵可加行,不加列（避免破坏"3 种处理方式"的分法）

## 附录:自检 4 问

每次大任务结束,AI 自问一次（作为响应最后一段,不计入正文）:

1. 我有没有先输出"目标+路径+验证"？
2. 我有没有让用户确认,还是直接做了？
3. 调研和决策是否分得清？
4. 改完有没有给"为什么"和"下一步"？
