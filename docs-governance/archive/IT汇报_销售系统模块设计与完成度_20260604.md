## 一、项目概述

销售管理系统是一个覆盖报价管理、合同审核、标书生成的一体化平台。系统共规划9大业务模块，22个功能需求点（REQ）。

前端采用Next.js 14 + React 18 + TypeScript技术栈，UI层使用Tailwind CSS和shadcn/ui组件库。后端基于Next.js API Routes，通过Prisma ORM连接Supabase（PostgreSQL + Auth）数据库。AI服务采用三级降级策略：本地LM Studio模型为首选项，云端模型为备用，规则引擎为兜底方案。OCR解析使用PaddleOCR。文件存储支持S3兼容服务及MinIO本地部署。缓存与消息队列使用Redis（Upstash）。监控集成Sentry。持续部署通过GitHub Actions CI接入Vercel。

### 2.2 系统架构（分层视图）

客户端层（Web/iPad）通过Next.js Middleware进入系统，该层负责鉴权校验、限流熔断及Sentry错误上报。

API Gateway层统一路由管理，包括：
- /api/auth/* 认证相关接口
- /api/quotes/* 报价中心接口
- /api/contracts/* 合同审核接口
- /api/configs/* 配置中心接口
- /api/tenders/* 标书中心接口

服务层分为四大块：
- 业务服务：报价、合同、标书、配置四大中心
- AI服务：本地LM Studio、云端OpenAI兼容、规则引擎三级降级
- 事件总线：基于Redis Stream的异步事件队列
- 后台服务：Admin管理后台、定时任务（cron）

数据层采用Supabase托管的PostgreSQL，当前包含16张业务表，通过16个迁移文件管理Schema演进。

### 2.3 AI服务三级降级策略

第一级为本地LM Studio模型，作为默认处理引擎。当单次调用超过45秒或发生OOM时，自动降级至第二级。

第二级为云端OpenAI兼容模型，作为本地模型的热备份。

第三级为规则引擎，仅执行结构化规则检查，返回结果中标记"AI分析不可用"提示。

文档路由阈值：15页以内整体送入本地模型；15至40页分段处理；超过40页整体上云。用户可手动强制切换至云端模型。

业务规则变更：
- 每项ASK仅允许一次回答，移除PARTIAL/INSUFFICIENT/VERIFIED循环状态
- ASK回答改为必填，未完成时硬关单，API返回422状态码及PENDING_ASKS_BLOCK错误
- ASK由上传人触发，澄清人入报，报告中显式展示ASK列表、姓名、角色、时间
- 零风险场景需填写no_ask_reason字段说明
