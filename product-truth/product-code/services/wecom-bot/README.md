# 企微智能机器人长连接接收服务

当前提供连接诊断：认证、心跳、断线恢复和停止。收到消息只计数，不保存正文、不回复、不执行订单；日志中的 `business_ready` 固定为 `false`。连接成功不能作为下单、取消或轨迹回传的验收结果。

## 运行

当前部署选择：先在用户本机联调，暂不购买云资源（2026-10-19 用户确认）。本机休眠、关机或退出接收进程会中断机器人连接。2026-10-19 已用用户截图中的 Bot ID 与用户提供的 Secret 通过真实企微认证；探测成功后已主动断开，尚未开启常驻业务服务。不得把一次认证通过标成持续在线。

需要 Node.js 22 或以上，以及能够访问企微的持续运行环境。复用已有服务器或容器，不需要开放入站回调端口。

在本目录执行 `npm ci --ignore-scripts`。通过宿主环境的秘密配置注入 `WECOM_BOT_ID` 和 `WECOM_BOT_SECRET`；不要把实际值写入源码、启动命令参数或日志。示例文件只列变量名。

- `npm test`：离线连接状态及凭据泄漏回归。
- `npm run probe`：完成认证后立即断开；失败返回非零退出码。
- `npm start`：持续监听，用于接入诊断。生产业务尚未接入。

先运行单次探测。只有日志出现 `phase: connected` 且 `authenticated: true` 才算认证通过；`authenticating` 只是套接字已建立。认证拒绝时保留数字错误码并停止，核对当前有效的机器人凭据后再启动，不能靠进程守护无限重试错误凭据。

认证通过后可由已有进程管理器管理单个实例。实例收到 SIGTERM 或 SIGINT 会主动断开；网络中断由 SDK 重连。当前没有健康检查 HTTP 端口，不能把进程存活视为认证成功。部署前还需结合实际服务器确认进程管理、秘密注入及日志策略。

## 后续迁移

服务器部署复用本目录与锁定依赖，将凭据注入新宿主环境。先停止本机实例，再启动服务器实例并确认重新认证成功，避免同一机器人多个连接相互挤下线。迁移不应改动业务权限、顺丰账户或现有配置数据；连接验证和业务验收分别记录。

## 配置中心

机器人配置默认提供长连接 Bot ID / Secret 保存入口，使用原有服务端加密存储。修改已保存项时留空 Secret 会保留原值，更换 Bot ID 必须同时提供对应 Secret。旧 URL 回调配置独立保留，不会自动转换或删除。当前保存状态不等于本机进程在线；业务桥接与健康状态回报另行验证。
