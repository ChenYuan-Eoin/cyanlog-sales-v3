# 纷享专用出口程序（WP91 / WP94）

> **当前用途限制（IN-20261109-016/017，优先于下文历史部署说明）：** 云电脑仅限用户明确启用的企微机器人；既有纷享转发属于待纠正依赖，不得据本说明继续打开云电脑管理页、重启或发布。历史固定出口和“轻依赖”记录不延续为授权。先核实获准生产服务的直连能力及业务影响，再按明确授权处理退出；不得擅自停服。完整规则见仓库根目录 `AGENTS.md` 的“云电脑与本地电脑使用边界”。

组织连接验证、目录和对象元数据读取直接访问纷享官方 API，不再在失败时转交云电脑。官方拒绝响应保留给调用方，不以转发失败掩盖白名单或权限错误。其他历史登录/身份入口只有在三项 `FXIAOKE_EGRESS_*` 配置全部停用后才恢复直连；整体退出必须验证这些配置及相应真实路径，不能仅凭目录代码修改宣称完成。

以下为既有转发的历史运行与退出参考，不是继续部署授权：正式站 → 加密短期请求 → 现有主机主动领取 → 纷享官方 API → 加密结果 → 正式站。

历史部署使用已有云主机；IN-20261105-012允许具备实证降级的轻依赖。WP92的组织连接验证和目录读取优先直接访问官方API，仅网络不可达、超时、HTTP 5xx或明确IP限制才尝试既有转发；凭据、权限、限流和数据格式错误不通过换路径掩盖。纷享出口与已放弃的企微接收进程是独立服务，组织同步不以企微运行状态作为前置。运行不依赖远程桌面、浏览器窗口或持续监看屏幕。它不监听公网端口，也不是通用代理。只允许应用鉴权、固定正式回调地址的 OAuth 授权码交换，以及 DepartmentObj、PersonnelObj 的固定字段只读查询；不能寄件、修改 CRM、任意抓取 URL 或跨组织领取。

## 发布边界

WP91 固定出口已按 `IN-20261028-007` 使用既有主机启用；历史连接与目录预览不代表 WP94 员工登录已验收。WP94 本次候选补齐 callback 的企业 transport，并在共享协议中只放行 `authorization_code` 的固定请求结构：精确官方 token URL、UUID v4 trace、JSON headers、五个必需字段及 `https://sales.cyanlog.icu/api/auth/fxiaoke/callback`。保留原 `app_secret` 规则。

网站和主机都使用 `protocol.mjs`，发布时必须核对两端版本兼容。WP92 切换期间，本轮新主机协议支持 `main_department` / `vice_departments` + `_id` 游标的完整人员请求，明确员工主属与附属部门；同时保留两种旧站点请求（`main_department` 简版 + offset，以及 `data_own_department` 旧版 + 游标）以便版本回退；新目录请求仍要求精确总数、固定前置条件与稳定排序。若实际环境仍需要转发路径，先更新既有worker的共享协议，再部署网站；直连可用时，转发主机不参与目录读取。保留既有服务的版本回退能力，不新增常驻进程。本次不需要新迁移、令牌或白名单变更；复用原受保护运行环境文件。发布授权仍按当前 WP92 的精确候选与范围判断，旧连接验收不得代替真实目录范围与切源验收。

新增两张服务端专用表：运行心跳一行/企业、短期加密请求表。普通账号和匿名角色无表与 RPC 权限。主机不持有数据库 service-role 密钥或全站加密主密钥。请求最长有效 20 秒，领取采用原子锁和随机租约；完成后立即消费删除，超时/取消清理，主机领取时清理已过期行。异常终止遗留的密文可能保留到下次清理，但过期后不可领取或写回。

Realtime 只广播空唤醒信号，不含任务 ID、企业 ID、任何凭据或通讯录数据。实际领取/回写必须通过指定企业的专用随机凭据。空闲时每分钟一次心跳/清理，约 1,440 次请求/天；另有一个 Realtime 连接和实际业务请求。复用现有资源不等于用量为零，启用前须核对现有额度。

## 系统侧配置（运维项，不放在业务表单）

| 环境项 | 内容 |
|---|---|
| `FXIAOKE_EGRESS_ORG_ID` | 本次允许领取的系统企业 UUID |
| `FXIAOKE_EGRESS_TOKEN_SHA256` | 主机随机令牌的 SHA-256；服务端仅保存摘要 |
| `FXIAOKE_EGRESS_ALLOWED_IP` | 已核实并写入纷享白名单的单个 IPv4 |

完整配置只作用于指定企业。WP92直连请求无需读取转发配置；只有启用备选转发时才验证配置、心跳和指定出口。配置残缺时不向主机排入凭据。原有登录专用transport保持原行为，不属于此次组织同步降级改动。专用令牌是 32–64 字节随机值的十六进制编码，应通过受保护配置渠道生成/分发，不能放在命令参数、代码、聊天或日志。

## 主机配置

在受保护的 `runtime.env`（目录 0700，文件 0600）中保存：

```dotenv
FXIAOKE_EGRESS_TOKEN=<本机专用随机令牌>
SUPABASE_PUBLISHABLE_KEY=<现有 cyanlog-sales-v3 的 publishable key>
```

运行仅需 Node.js 22+。将本目录的 `worker.mjs`、`protocol.mjs`、`package.json` 和 `package-lock.json` 放进独立版本目录，执行 `npm ci --ignore-scripts --omit=dev`。通过 `FXIAOKE_RUNTIME_ENV` 指向上述私有文件，再运行 `node worker.mjs`。不复制网站环境变量或使用数据库管理员密钥。

采用独立的 systemd 服务启动，只管理纷享服务，不恢复或检查企微作为验收条件。服务的 `WorkingDirectory` 和 `ExecStart` 必须指向已验证版本及实际 Node 路径，`Restart=on-failure`，开机启动；标准输出进 journal。安装、启用和设置白名单属于发布动作，不由此文档自动授权。

更新时使用独立版本目录，保留旧目录和 unit 备份；先验证新包 hash、语法和共享协议，再切换现有 `price-v3-fxiaoke.service`，不并行运行第二个领取者。失败时恢复原 unit 的版本路径并重启原 worker，核对纷享固定出口心跳及只读目录请求。此版本回滚不等于停用整个固定出口。

## 检查与失败处理

1. 主机通过 HTTPS 查询自己的出口，每 45 秒以上刷新；查询失败时不领取请求。服务端将报告的地址与配置比对，不自动修改白名单。
2. IP 不匹配时标记 `ip_changed`；网站明确要求核对并更新白名单。心跳超过 90 秒失效，网站拒绝排入包含凭据的请求。
3. 白名单内的地址不代表纷享授权成功。必须以真实 `errorCode=0`、服务端自动获取企业账号、保存回读和目录预览证明接通。
4. `worker_error / WORKER_AUTH_REJECTED` 表示专用凭据无效，停止处理；修复配置后再启动。`CONNECTION_FAILED` 只记录分类，不输出异常原文、凭据或人员信息。
5. 停用转发时移除系统侧三项配置并停止这个专用进程；现有企微进程与组织数据不受此程序操作。已保存纷享连接继续保留，回退直连不代表白名单问题已解决。

## 组织同步降级验收（WP92）

- 单次直连最多6秒，保留调用方的整体超时/取消信号；只允许应用鉴权与固定目录查询，不接管OAuth授权码或登录身份查询。
- 直连遇到网络或IP限制时，只尝试现有指定企业的转发。一次目录读取中选用转发后，主机中途离线可重新尝试直连；不跨请求或跨企业缓存路线。
- 两条路径均不可用时返回明确的`DIRECTORY_SOURCE_UNAVAILABLE`；不同路由均不返回空目录冒充成功。差异生成在完整读取成功后才写计划，失败不覆盖旧计划、不应用部门或人员。
- 组织架构页面从本系统原生成员和部门表回读，不依赖提供方、心跳或转发任务。主机停机时，已有目录查看和原有管理仍可继续。新来源数据的获取不能在所有合法网络路径均失败时伪造成功。
- 必须区分隔离故障测试与当前部署的实际连通性。受保护Preview缺少对应生产凭据、或敏感变量不可读取，都不能证明纷享直连成功或被IP拒绝。Production仍须以实际调用结果验证；不得放宽白名单或默认新购出口。

生产验收仍必须在用户现有 Chrome、`sales.cyanlog.icu` 真实操作；本地测试或主机在线都不能代替。
