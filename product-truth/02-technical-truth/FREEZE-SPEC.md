## 1. 状态机口径（优先级：阻塞）

### 1.1 报价单状态机（必须统一）

**冻结决策**:
```
状态总数: 6个
  - DRAFT（草稿）
  - PENDING_APPROVAL（审批中）
  - APPROVED（已批准）
  - SENT（已发送）
  - CONFIRMED（已确认）
  - REJECTED（已拒绝/已退回）

状态转移:
  DRAFT → PENDING_APPROVAL（提交审批）
  PENDING_APPROVAL → APPROVED（审批通过）
  PENDING_APPROVAL → REJECTED（审批驳回）
  REJECTED → DRAFT（修改后重新提交）
  APPROVED → SENT（发送客户）
  SENT → CONFIRMED（客户确认）
  SENT → REJECTED（客户拒绝）

禁止转移:
  - CONFIRMED 不可回退
  - PENDING_APPROVAL 不可直接编辑
```

**需要删除/修正**: 主文档第2章重复的状态机描述，以本冻结口径为准。

### 1.2 合同审核状态（必须统一）

**冻结决策**:
```
状态总数: 5个
  - PENDING（待审核）
  - PARSING（解析中）
  - ANALYZING（分析中）
  - COMPLETED（审核完成）
  - FAILED（审核失败）

状态转移:
  PENDING → PARSING（开始审核）
  PARSING → ANALYZING（解析完成，开始规则扫描）
  ANALYZING → COMPLETED（审核成功）
  ANALYZING → FAILED（规则引擎或模型全部失败）

失败后可操作:
  FAILED → PENDING（重新触发审核）
```

## 2. 审批口径（优先级：阻塞）

### 2.1 审批状态定义

**冻结决策**:
```
审批单独立状态:
  - PENDING（待审批）
  - APPROVED（已通过）
  - REJECTED（已驳回）
  - TRANSFERRED（已转交）
  - TIMEOUT（已超时）

与报价单状态关系:
  审批单 PENDING → 报价单 PENDING_APPROVAL
  审批单 APPROVED → 报价单 APPROVED
  审批单 REJECTED → 报价单 REJECTED（回到草稿可编辑）
```

### 2.2 驳回后回到哪一态

**冻结决策**:
- 驳回后报价单状态 = REJECTED
- 用户操作：编辑后重新提交（DRAFT → PENDING_APPROVAL）
- 保留审批历史，显示驳回原因

### 2.3 超时处理

**冻结决策**:
```
超时时间:
  - 普通审批: 24小时
  - 紧急审批: 4小时

超时前提醒:
  - 超时前2小时: 应用内+飞书提醒

超时后动作:
  - 自动升级给上级
  - 总超时48小时: 自动驳回

自动驳回后:
  - 报价单状态 = REJECTED
  - 通知申请人"审批超时，请重新提交或联系管理员"
```

## 3. 合同审核动作模型（优先级：阻塞）

### 3.1 上传 vs 提交审核 的 API 边界

**冻结决策**:
```
上传合同（独立API）:
  POST /api/contracts/upload
  动作: 保存文件到Storage，创建合同记录，状态=PENDING
  返回: contract_id

提交审核（独立API）:
  POST /api/contracts/:id/analyze
  前提: 合同状态必须是 PENDING 或 FAILED
  动作: 
    1. 校验状态
    2. 创建审核任务（异步）
    3. 状态变更为 PARSING
    4. 返回 review_id
```

### 3.2 审核执行模型（同步 vs 异步）

**冻结决策**:
```
提交审核 API: 同步返回，立即返回 review_id
审核执行: 完全异步（后台队列）

状态查询:
  GET /api/contracts/:id
  返回当前状态和最新审核结果

结果推送（可选MVP后）:
  审核完成后飞书通知（不做则靠前端轮询）
```

## 4. AI 平台与执行环境口径（现行阻塞口径）

**替代关系**：2026-05-28 冻结的固定 LM Studio/云模型/规则引擎三级链、固定页数阈值与固定超时已废止。现行唯一依据为 `product-truth/feature-packets/F012-ai-runtime-config.md`。

### 4.1 已发布运行计划（唯一来源）

**现行冻结决策**：

`业务用点 → 应用绑定 → AI 应用 → 路由策略 → 模型目录 → Provider 连接`

- 业务模块只能选择已发布 AI 应用，不得直接写 Provider、模型 ID 或密钥；
- 路由策略保存有序模型候选、单次超时和全部失败动作；具体数值随发布版本进入快照，不再使用全局固定阈值；
- 规则引擎独立执行已发布业务规则，不是 Provider、模型候选或模型失败兜底层；
- 正式运行不得读取旧 ModelPolicy、环境变量或开发工具代理作为静默旁路。

### 4.2 配置顺序与环境投影

**现行冻结决策**：

- `configured route` 保留管理员发布的完整候选顺序；
- 本机 `effective route` 可包含 local 与 cloud Provider；
- Hosted `effective route` 排除仅本机可达的 Provider，并从首个可执行 cloud 候选开始连续编号；
- 环境排除不生成 invocation、不增加尝试次数、不算失败或降级；
- Hosted 如果没有任何可执行候选，必须失败关闭并提示补充公网可达模型；
- 运行快照同时保存 configured 与 effective 顺序，后者必须是前者的有序子序列。

### 4.3 失败与验收证据

**现行冻结决策**：

- 可执行模型按已发布路由依次尝试；全部失败后只执行路由配置的“转人工”或“停止”；
- Provider probe 只代表当次草稿连接或最小生成，不持久化为生产健康状态，也不触发自动切云；
- 真实可用性必须由同一运行计划下的业务 `ReviewRun`、`model_invocations`、token 和连续尝试记录验收；
- 规则引擎输出只证明确定性规则结果，不能生成或替代模型调用证据。

## 5. 配置三层归属（优先级：不阻塞，但建议冻结）

**冻结决策**：
```
所有配置必须归属到以下三层之一：

1. 可配置能力域（Config Capability）
   - 合同审核规则配置
   - 报价规则配置
   - AI模型连接配置
   - 组织权限配置

2. 能力域内部对象（Capability Objects）
   - 合同规则域: 结构化规则、语义规则、版本管理
   - 报价与审批域: 税率规则、折扣阈值、审批流程
   - 全局 AI 平台域: Provider 端点与认证、模型目录、AI 应用、路由策略
   - 组织权限域: 部门架构、角色权限、数据范围

3. 业务工作区消费（Business Consumption）
   - 合同审核页: 读取合同规则执行审核
   - 已注册业务用点: 选择并消费已发布 AI 应用
   - 报价创建页: 读取税率规则计算金额
   - 审批处理页: 读取审批流程执行流转

禁止: 业务工作区直接修改配置（必须通过配置中心）
```

### 5.3 审批转交流程（必须冻结）

**冻结决策**:
```
转交触发：
  审批人点击"转交"按钮
  
转交范围：
  - 同部门内有审批权限的成员
  - 或指定具体人员（需有审批权限）
  
转交后状态：
  - 原审批人：不再收到提醒，失去审批权限
  - 新审批人：收到"转交审批"通知，显示转交原因
  - 申请人：收到"审批已转交"通知
  
转交限制：
  - 一个审批单最多转交3次
  - 转交后审批时效重新计算（从转交时刻起24h）
```

### 5.4 配置生效机制（必须冻结）

**冻结决策**:
```
保存 vs 发布：
  - 保存：创建新版本，不自动生效
  - 发布：标记版本为生效，新审核使用此版本
  
生效时机：
  - 立即生效：发布后立刻影响新审核/新报价
  - 定时生效：设置future时间生效（如次月1日税率调整）
  
生效范围：
  - 仅新单据：发布后新创建的报价/合同使用新配置
  - 全量生效（慎用）：影响所有未完成的单据
  
MVP冻结：仅支持"保存+立即发布"，不支持定时生效
```
