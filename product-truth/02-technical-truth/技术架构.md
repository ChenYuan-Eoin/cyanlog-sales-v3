## 1. 服务间调用电路

```
客户端请求
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│                      API Gateway                         │
│  • 路由分发                                             │
│  • 认证鉴权                                             │
│  • 限流熔断                                             │
└────────────────┬───────────────────────────────────────┘
                 │
    ┌────────────┼───────────────┐
    ▼            ▼               ▼
  业务模块      事件总线         全局 AI 平台
    │            │               │
    ▼            ▼               ▼
┌────────┐   ┌────────┐   ┌────────────────┐
│报价/合同│   │事件队列│   │业务用点与应用绑定│
│标书等  │   │与消费者│   │AI 应用与模型路由 │
└───┬────┘   └───┬────┘   │模型目录与 Provider│
    │            │        └───────┬────────┘
    ▼            │                ▼
┌────────┐       │        ┌────────────────┐
│规则引擎│       │        │本机或云端模型服务│
│确定性判定│      │        └───────┬────────┘
└───┬────┘       │                │
    └────────────┴────────┬───────┘
                          ▼
                 数据库 / 文件 / 审计证据
```

规则引擎属于业务规则执行面，不属于 AI Provider、模型目录或模型降级层。报价、合同、标书及未来业务模块通过稳定业务用点消费同一全局 AI 平台，不直接绑定模型地址。

## 2. API 网关路由电路

### 2.1 路由规则

```
/api/auth/*      → Account 服务
```

### 2.2 网关功能

| 功能 | 说明 | 实现 |
|------|------|------|
| 路由分发 | 按路径路由到不同服务 | Next.js API Routes |
| 认证鉴权 | Token验证、权限检查 | Middleware |
| 限流熔断 | 防止服务过载 | Redis + Rate Limit |
| 日志记录 | 请求/响应日志 | Winston |
| 错误处理 | 统一错误响应格式 | Error Handler |

## 3. 事件总线电路（EventBus）

### 3.1 事件类型

| 事件 | 触发条件 | 消费者 |
|------|---------|--------|
| QuoteCreated | 报价单创建 | 日程管理、通知服务 |
| QuoteSent | 报价单发送 | 日程管理、CRM同步 |
| QuoteConfirmed | 报价确认 | 合同生成、赢单统计 |
| ContractUploaded | 合同上传 | OCR解析、审核任务 |
| ContractReviewed | 审核完成 | 通知服务、报告生成 |
| ApprovalRequested | 审批请求 | 通知服务、日程管理 |
| ApprovalCompleted | 审批完成 | 报价状态更新、通知服务 |

### 3.2 事件总线架构

```
生产者 ────► Redis Stream ────► 消费者
    │                            │
    ├── Event: QuoteCreated      ├── 消费者A: 日程管理
    ├── Event: QuoteSent         ├── 消费者B: 通知服务
    ├── Event: ContractUploaded   ├── 消费者C: OCR解析
    └── Event: ApprovalRequested └── 消费者D: 审核任务
```

## 4. AI 平台模型能力与环境投影

本节现行真相由 `F012-ai-runtime-config.md` 定义，取代旧 F022 的固定“本地 → 云端 → 规则引擎”三级链、固定页数阈值和全局超时。

### 4.1 全局平台与唯一运行计划

AI 平台可被任意已注册业务模块消费，运行依赖关系为：

`业务用点 → 应用绑定 → AI 应用 → 路由策略 → 模型目录 → Provider 连接`

- Provider 连接只管理端点、协议、认证和运行位置；
- 模型目录管理同一 Provider 下的具体模型及通用能力；
- AI 应用定义可复用能力，业务用点只选择已发布应用；
- 路由策略保存管理员批准的有序模型候选、单次超时和全部失败动作；
- 正式业务运行只消费完整、已发布且不可漂移的运行计划，不读取旧 ModelPolicy、环境变量或开发工具代理作为旁路。

### 4.2 执行环境投影

运行计划必须同时保留管理员配置顺序和当前环境实际可执行顺序：

| 环境 | 投影规则 | 审计口径 |
|------|----------|----------|
| 本机 | 可保留 local 与 cloud 候选 | 按实际调用顺序记录 invocation |
| Hosted | 排除用户电脑或局域网内的 local Provider，从首个可执行 cloud 候选开始 | 环境排除不生成 invocation、不增加尝试次数、不算失败降级 |
| Hosted 且全部候选均为 local | 失败关闭 | 提示补充公网可达模型，不静默切换旧配置 |

实际执行顺序必须是管理员配置顺序的有序子序列；环境投影不得覆盖发布配置，也不得改写历史运行快照。

### 4.3 失败、规则与证据

- 候选模型按路由策略逐个尝试；具体超时属于发布路由，不存在全系统固定 45 秒或按页数强制切云的通用规则；
- 所有可执行模型失败后，只执行路由明确配置的“转人工”或“停止”，不能把规则引擎冒充为模型成功；
- 规则引擎独立执行已发布业务规则的确定性判定，保留规则快照与证据，但不生成 `model_invocations`；
- Provider probe 只证明当次连接或最小生成，正式可用性必须由真实业务运行的 `ReviewRun`、`model_invocations` 和 token 证据证明。

## 5. 服务间调用模式

### 5.1 同步调用

```typescript
// 同步调用（适用于需要立即响应的场景）
async function getQuoteDetails(quoteId: string) {
  const response = await fetch(`/api/quotes/${quoteId}`);
  return response.json();
}
```

### 5.2 异步调用

```typescript
// 异步调用（适用于耗时操作）
async function analyzeContract(contractId: string) {
  // 提交分析任务
  const task = await fetch('/api/contracts/analyze', {
    method: 'POST',
    body: JSON.stringify({ contractId }),
  });

  // 返回任务ID，前端轮询
  return task.json(); // { taskId: 'xxx', status: 'PENDING' }
}
```

### 5.3 事件驱动

```typescript
// 事件驱动（适用于解耦场景）
// 生产者
async function publishQuoteCreated(quote: Quote) {
  await eventBus.publish('QuoteCreated', {
    quoteId: quote.id,
    customerId: quote.customerId,
    amount: quote.totalAmount,
  });
}

// 消费者
async function handleQuoteCreated(event: Event) {
  // 创建跟进提醒
  await createFollowUpReminder(event.quoteId);
  // 通知CRM
  await syncToCRM(event);
}
```

## 6. 缓存策略电路

### 6.1 缓存层级

| 层级 | 技术 | 用途 | 过期时间 |
|------|------|------|----------|
| L1 浏览器缓存 | Cache-Control | 静态资源 | 1年 |
| L2 CDN缓存 | Vercel Edge | 页面缓存 | 60秒 |
| L3 应用缓存 | Redis | API响应 | 5分钟 |
| L4 数据库缓存 | PostgreSQL | 查询结果 | 30分钟 |

### 6.2 缓存策略

```
缓存策略：

1. 静态资源（CSS/JS/图片）
   ├── 长期缓存（Cache-Control: max-age=31536000）
   └── 文件名包含hash

2. API响应
   ├── GET请求 → 可缓存
   ├── POST/PUT/DELETE → 清除缓存
   └── 缓存键：URL + 用户ID + 查询参数

3. 数据库查询
   ├── 热点数据 → 内存缓存
   ├── 配置数据 → 本地缓存
   └── 会话数据 → Redis缓存
```

## 9. MVP 架构约束

### 9.1 架构原则

1. **单体优先**：MVP阶段使用Next.js单体架构，不拆分微服务
2. **本地优先**：AI模型默认使用本地LM Studio，云端作为备用
3. **最小依赖**：核心功能不依赖外部系统（CRM等），支持独立运行
4. **渐进式扩展**：架构预留扩展点，支持后续演进

### 9.2 性能约束

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 页面加载 | < 3s | 首屏加载时间 |
| API响应 | < 200ms | 简单查询 |
| 文件上传 | < 10s | 10MB以内 |
| AI分析 | < 45s | 本地模型 |
| 并发用户 | 50 | 同时在线 |

### 9.3 安全约束

| 约束 | 说明 |
|------|------|
| HTTPS | 所有通信必须加密 |
| Token认证 | API请求必须携带有效Token |
| 输入校验 | 所有输入必须校验 |
| SQL注入防护 | 使用ORM，禁止拼接SQL |
| XSS防护 | 输出编码，防止XSS |
| CSRF防护 | 使用SameSite Cookie |
| 敏感数据加密 | 密码bcrypt，Token随机生成 |
