# 循环架构图 #4：业务闭环循环

> **参考来源**: ONES "需求-任务-发布-复盘" 完整闭环、PRD 驱动开发流程

## 节点流向图

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                      业务闭环循环 (Business Loop)                             │
│                      参考: ONES 需求-任务-发布-复盘                           │
└─────────────────────────────────────────────────────────────────────────────┘

     ┌───────────────┐
     │    需求产生   │  ← 业务需求或用户反馈
     │               │    来源: 用户反馈 / 业务分析 / 竞品研究
     │  • 用户痛点   │
     │  • 业务目标   │       参考: ONES 需求管理
     │  • 技术债务   │
     └───────┬───────┘
             │
             ▼
     ┌───────────────┐
     │   REQ 登记    │  ← 需求进入注册表
     │               │    代码: product-truth/REQ_REGISTRY.yml
     │  • 唯一 ID    │       参考: REQ 状态机规范
     │  • 状态标记   │
     │  • 优先级     │
     │    P0/P1/P2   │
     └───────┬───────┘
             │
             ▼
     ┌───────────────┐
     │  Feature      │  ← 功能闭环 Packet 创建
 │   Packet 设计   │    文档: product-truth/feature-packets/REQ-xxx.md
     │               │
     │  1. 需求分析  │       结构: 9 章节模板
     │  2. 技术方案  │
     │  3. 验收标准  │
     │  4. 风险识别  │
     └───────┬───────┘
             │
             ▼
     ┌───────────────┐
     │    开发实现   │  ← 代码编写
     │               │    代码: product-truth/product-code/
     │  • 分支开发   │       分支: feature/req-xxx
     │  • 代码审查   │
     │  • 测试覆盖   │
     └───────┬───────┘
             │
             ▼
     ┌───────────────┐
     │  Implement    │  ← 实施真相记录
 │   Manifest      │    文档: 04-implementation-truth/
     │               │
     │  • API 合约   │       格式: YAML/JSON
     │  • 测试结果   │
     │  • 部署记录   │
     └───────┬───────┘
             │
             ▼
     ┌───────────────┐
     │    功能发布   │  ← 部署到生产环境
     │               │    流程: CI/CD → Vercel
     │  • 灰度发布   │       监控: Vercel Analytics
     │  • 全量发布   │
     │  • 版本标记   │
     └───────┬───────┘
             │
             ▼
     ┌───────────────┐
     │   状态更新    │  ← REQ 状态流转
     │               │    文档: REQ_REGISTRY.yml 更新
     │  • packet     │       状态: drafted → released
     │  • 更新状态   │
     │  • 代码位置   │
     │    回写       │
     └───────┬───────┘
             │
             ▼
     ┌───────────────┐
     │    效果复盘   │  ← 功能效果验证
     │               │    来源: 使用数据 + 用户反馈
     │  • 数据指标   │       对比: 预期 vs 实际
     │  • 用户反馈   │
     │  • 改进建议   │
     └───────┬───────┘
             │
             │
             └──────────────→ [回到 需求产生] or [结束] ◄──┐
                                                        │    │
                              ╔═════════════════════════╝    │
                              ║                              │
                              ║  闭环完成                    │
                              ╚══════════════════════════════╝

┌─────────────────────────────────────────────────────────────────────────────┐
│                          4 个回写点 (Write-back Points)                      │
└─────────────────────────────────────────────────────────────────────────────┘

1. REQ_REGISTRY.yml             ← 状态更新
2. feature-packets/REQ-xxx.md   ← packet 完成标记
3. 03-design-truth/             ← 设计资产归档
4. 04-implementation-truth/     ← 实施证据归档
```

## 实际代码路径

| 组件 | 路径 | 状态 |

| Feature Packets | `product-truth/feature-packets/` | ✅ 已存在 |
| 设计真相 | `product-truth/03-design-truth/` | ✅ 已存在 |
| 实施真相 | `product-truth/04-implementation-truth/` | ✅ 已存在（新建） |

## 失败时可观测输出

| 故障点 | 现象 | 输出位置 |
|--------|------|----------|
| REQ 状态未更新 | packet 已发布但 registry 未改 | git diff |
| 代码未回写位置 | packet 缺少代码路径 | `checks/check-09-business-loop.sh` |
| manifest 缺失 | 发布后无实施证据 | 04-implementation-truth/ 目录检查 |

## 人工介入触发条件

| 触发条件 | 响应时间 | 介入角色 |
|----------|----------|----------|
| REQ 状态与代码不符 | 开发完成时 | 开发者 |
| packet 超过 2 周未关闭 | 每周期 | 项目经理 |
| 发布后无复盘记录 | 发布后 1 周 | 产品负责人 |
