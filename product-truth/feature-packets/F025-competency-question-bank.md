**Status**: confirmed

**Depends On**: `F024`, `F015`, `F016`, `F017`

## 1. 单元定义

**目标**：把岗位标准、学习内容映射、题库对象和组卷蓝图收成一个独立能力面，为后续模拟考、正式考和补学复测提供稳定输入。

`F025` 不是“知识库加一个考试标签”，也不是“考核系统里的题目录入页”。

它要回答的是：
1. 一个培养岗位需要达到哪些能力标准
2. 每项能力标准应该由哪些学习内容支撑
3. 哪些题目或情景题可以证明这项能力是否达标
4. `F026` 在生成具体考核前，应该按什么蓝图组织题目和分值

这里有两个必须先锁死的判断：

**内容源 != 题库对象**

- `F015-F017` 解决的是“资料是什么、能不能查到、能不能被引用”
- `F025` 解决的是“这些资料支持哪些能力标准、能沉淀成哪些题目、如何进入题库和组卷蓝图”

**胜任力项 != 考试成绩**

- `F025` 定义的是能力标准和可被验证的证据结构
- `F026` 记录的是具体某次模拟考、正式考、补考的得分与结果

**这包拥有的内容**：
- 胜任力模型、维度、分级
- 培养岗位与胜任标准映射
- 学习内容引用与学习映射规则
- 题库对象、题目版本、标签、难度、题型
- 题目与知识来源追溯
- 面向 `F026` 的出题蓝图 / 组卷蓝图

**这包不拥有的内容**：
- 通用案例库 / 文档库 / 资质库 CRUD
- 通用搜索、全文检索、向量检索底座
- 引导阶段任务与导师推进（属于 `F024`）
- 具体考试日程、考试场次、评分执行、认证结果归档（属于 `F026`）

## 3. 用户与使用场景

### 3.1 培训运营 / 管理员
- 维护岗位标准和能力模型版本
- 维护学习映射和默认学习包
- 发布可供 `F026` 消费的考核蓝图

### 3.2 业务经理
- 查看不同培养岗位的达标标准
- 确认哪些能力项为必达项
- 判断不同岗位是否需要不同难度与通过线

### 3.3 内容维护人 / SME
- 从案例、技术文档、资质材料中挑选可复用内容
- 编写题目、审核题目、维护题目版本
- 标注题目适用的能力项、题型和难度

### 3.4 考核运营
- 为某类考核选择已发布蓝图
- 校验蓝图覆盖面、题量、题型、分值
- 将蓝图交由 `F026` 生成具体考核计划

## 4. 核心对象

### 4.1 胜任力模型

- `competency_models`
- `competency_model_versions`
- `competency_dimensions`
- `competency_items`
- `competency_item_levels`

说明：
- 模型需要版本化，否则岗位标准一改，历史题库映射和历史考核蓝图都会漂移
- 维度解决分类，能力项解决可验证标准，等级解决达标深度

推荐字段：
- `model_code`
- `model_name`
- `job_family`
- `applies_to_path_codes[]`
- `status`
- `published_at`

### 4.2 岗位标准映射

- `path_competency_requirements`
- `competency_requirement_versions`

说明：
- `F024` 的岗位路径回答“一个人走哪条成长路径”
- `F025` 的岗位标准映射回答“走到这条路径的人，哪些能力必须达到什么级别”
- 同一个能力模型可以被多个培养岗位复用，但不同岗位的目标等级、权重、是否必达可以不同

推荐字段：
- `path_code`
- `competency_item_code`
- `target_level`
- `weight`
- `is_required`
- `evidence_type`

### 4.3 学习内容映射

- `learning_mappings`
- `learning_mapping_sources`
- `learning_mapping_snapshots`

说明：
- 映射对象不是知识源本身，而是“某个能力项建议学什么”
- 内容源来自 `F015/F016/F017`
- 允许保留引用关系和必要快照，避免原始内容后续变更导致映射语义漂移

推荐来源类型：
- `CASE`
- `TECH_DOCUMENT`
- `BUSINESS_QUALIFICATION`

推荐字段：
- `competency_item_code`
- `source_type`
- `source_id`
- `source_version_hint`
- `mapping_type`：`MUST_LEARN` / `REFERENCE` / `ADVANCED`
- `snapshot_title`
- `snapshot_tags[]`

### 4.4 题库对象

- `question_bank_items`
- `question_bank_versions`
- `question_competency_links`
- `question_source_refs`
- `question_tag_sets`

说明：
- 题库对象必须独立于知识源对象
- 一个题目可以引用多个内容源、覆盖多个能力项，但应标记一个主能力项
- 已发布题目不能直接覆写，修改应产生新版本

推荐题型：
1. `SINGLE_CHOICE`
2. `MULTIPLE_CHOICE`
3. `TRUE_FALSE`
4. `CASE_ANALYSIS`
5. `SCENARIO_QA`
6. `ROLEPLAY_RUBRIC`

推荐字段：
- `question_code`
- `question_type`
- `difficulty`
- `primary_competency_item_code`
- `status`
- `reviewed_by`
- `published_at`

### 4.5 组卷蓝图

- `exam_blueprints`
- `exam_blueprint_versions`
- `blueprint_sections`
- `blueprint_rules`

说明：
- 蓝图不是具体某一次考试
- 蓝图定义的是按什么能力、题型、难度和分值结构去组织题目
- `F026` 只消费已发布蓝图，不反向修改蓝图定义

推荐字段：
- `blueprint_code`
- `blueprint_name`
- `target_path_codes[]`
- `assessment_scene`
- `duration_minutes`
- `total_score`
- `pass_line`
- `status`

## 5. 核心流程

### 5.1 定义能力标准

1. 运营或业务负责人确定培养岗位范围
2. 建立或选择一个胜任力模型版本
3. 按维度拆分能力项
4. 为岗位配置目标等级、权重和是否必达
5. 发布该版本，供学习映射和题库绑定

### 5.2 映射学习内容

1. 选择一个能力项
2. 从 `F015-F017` 中挑选案例、文档、资质内容
3. 标记为必学 / 参考 / 进阶
4. 必要时固化来源标题、版本、标签快照
5. 输出稳定学习映射，供 `F024` 或后续补学流程消费

### 5.3 生产与维护题库

1. 内容维护人新建题库对象
2. 编写题目版本、答案、解析、评分要点
3. 关联主能力项、附属能力项和来源素材
4. 审核通过后发布
5. 后续修改以新版本方式进入再次审核

### 5.4 产出组卷蓝图

1. 选择目标岗位路径或认证主题
2. 选择要覆盖的能力项集合
3. 配置题型比例、难度比例、分值和通过线
4. 绑定题目池筛选规则或指定题目范围
5. 发布蓝图版本，交给 `F026` 生成具体考核计划

## 6. 状态机

### 6.1 胜任力模型版本状态

```text
DRAFT -> PUBLISHED -> RETIRED
      \-> REWORK ----^
```

说明：
- 只有 `PUBLISHED` 版本可以被学习映射、题库和蓝图正式引用
- `RETIRED` 只表示停止新用，不表示删除历史关联

### 6.2 题目状态

```text
DRAFT -> IN_REVIEW -> PUBLISHED -> RETIRED
      \-> REWORK -----------^
```

说明：
- `DRAFT`：草稿
- `IN_REVIEW`：待审核
- `PUBLISHED`：可进入蓝图筛选范围
- `RETIRED`：停用，但保留历史引用

### 6.3 蓝图状态

```text
DRAFT -> PUBLISHED -> ARCHIVED
      \-> REWORK ----^
```

说明：
- `ARCHIVED` 用于被新蓝图替代后的历史保留
- 历史考核记录继续指向发布时版本

## 7. 默认结构建议

`F025` 先锁结构，不锁死最终业务内容条目。

### 7.1 默认能力维度建议
- 业务与行业理解
- 产品与方案理解
- 报价与商务协同
- 风险与合规判断
- 客户沟通与需求澄清
- 内部协作与推进能力

### 7.2 默认学习映射类型
- `MUST_LEARN`：未完成前不建议进入下一阶段考核
- `REFERENCE`：常规参考资料
- `ADVANCED`：进阶补充材料

### 7.3 默认题库标签轴
- 按岗位路径
- 按能力维度
- 按能力项
- 按题型
- 按难度
- 按知识来源
- 按适用场景（入门 / 认证 / 补学 / 复测）

## 8. 与其他 REQ 的边界

| 功能 | 拥有者 |
|------|--------|
| 组织树、成员归属、权限角色 | `F011` |
| 岗位路径、引导任务、试用期复核 | `F024` |
| 案例、文档、资质等内容源 | `F015 / F016 / F017` |
| 胜任力模型、学习映射、题库对象、组卷蓝图 | `F025` |
| 模拟考 / 正式考 / 补考、评分归档、认证结果 | `F026` |

这条边界必须稳定。

否则会出现三个常见问题：
1. 把知识库正文直接当题库
2. 把岗位标准直接混进考试结果
3. 把蓝图配置和具体考试场次做成同一对象

## 9. 数据建模原则

推荐强类型对象：
- `competency_models`
- `competency_model_versions`
- `path_competency_requirements`
- `learning_mappings`
- `question_bank_items`
- `question_bank_versions`
- `exam_blueprints`
- `exam_blueprint_versions`

关键原则：

1. **模板 / 标准 / 实例分层**  
   胜任力模型和蓝图是标准定义，具体考试实例属于 `F026`。

2. **来源引用与题库对象分层**  
   题目引用知识源，但不在题库侧反写知识源正文。

3. **版本优先于覆盖**  
   已发布模型、题目、蓝图的修改都应生成新版本，而不是直接覆盖。

4. **主能力项必须可追溯**  
   一个题目可以覆盖多个能力项，但必须能明确它主要验证什么。

5. **快照只保存必要元数据**  
   为了追溯稳定性，可以保存标题、版本、标签等快照；不要求复制整篇知识正文。

6. **能力标准不被成绩回写污染**  
   某次考试分数再高，也不应直接改写能力标准定义。

## 10. 客户端能力要求

### 10.1 能力标准配置台
- 维护胜任力模型与版本
- 查看岗位目标等级
- 查看必达项与权重

### 10.2 学习映射工作台
- 为能力项绑定知识来源
- 区分必学 / 参考 / 进阶
- 查看来源快照与当前源内容差异

### 10.3 题库工作台
- 创建和审核题目
- 按能力项、题型、难度筛选
- 查看题目来源追溯和版本历史

### 10.4 蓝图配置台
- 配置题量、分值、通过线
- 校验覆盖面
- 发布给 `F026` 消费

注意：
- 页面文案优先使用“能力标准 / 学习内容 / 试题库 / 组卷规则”等表达
- 不把内部设计边界直接当成前台产品文案
