# Feature Packet: F024-入职引导与岗位路径

**Created**: 2026-06-10  
**REQ ID**: F024  
**Status**: confirmed  
**Parent**: `F023-销售赋能与考核中心`  
**Depends On**: `F011`, `F018`, `F019`

---

## 1. 单元定义

**目标**：把新成员到岗后的引导动作和岗位成长路径独立出来，避免把岗位划分、导师协作、试用期任务散落到组织管理或知识库里。

`F024` 不是一个“欢迎页”或“消息清单”。

它要回答的是：
1. 新成员被放进哪个培养岗位
2. 这个岗位需要经历哪条成长路径
3. 每个阶段必须完成什么学习与演练
4. 试用期内在哪些节点需要经理/导师判断是否继续推进

这里有一个必须先锁死的判断：

**培养岗位 != 权限角色**

- `F011` 的 `role / user_roles` 解决的是“这个人能看什么、能做什么”
- `F024` 的 `role_path` 解决的是“这个人应该学什么、按什么路径成长”

两者可以关联，但不能互相替代。

**这包拥有的内容**：
- 入职引导模板
- 岗位分类与岗位路径
- 必学项清单
- 试用期里程碑
- 导师 / 协作人挂接规则
- 转岗后的重开引导规则

**这包不拥有的内容**：
- 用户创建、角色授予、组织归属调整
- 通用文档库或资料上传底座
- 通用日程派发底座
- 胜任力项定义和题库生产（属于 `F025`）
- 模拟考 / 正式考 / 补考编排（属于 `F026`）

## 3. 用户与使用场景

### 3.1 新成员
- 查看当前岗位路径
- 查看当前阶段必须完成的任务
- 知道下一次评审节点和通过条件

### 3.2 导师 / 协作人
- 接收带教关系
- 确认演练任务是否完成
- 对阶段表现给出结构化备注

### 3.3 经理
- 为成员指定培养岗位
- 决定阶段是否通过、打回或重开
- 判断是否进入下一阶段或转入后续考核

### 3.4 运营 / 管理员
- 维护岗位路径模板
- 维护引导模板版本
- 查看不同岗位的推进情况

---

## 4. 核心对象

### 4.1 岗位路径模板

- `role_paths`
- `role_path_versions`

说明：
- 一个培养岗位可以有多个版本
- 版本化是必须的，否则历史成员路径会被模板覆盖

推荐字段：
- `path_code`
- `path_name`
- `applies_to_role_codes[]`：关联哪些 `F011` 权限角色
- `job_family`
- `is_entry_path`
- `status`

### 4.2 引导模板

- `onboarding_templates`
- `onboarding_template_stages`
- `onboarding_template_tasks`

说明：
- 模板是岗位路径的展开
- 重点不是一大坨 checklist，而是分阶段任务包

推荐阶段：
1. `PREPARE`：到岗准备
2. `FOUNDATION`：基础认知
3. `PRACTICE`：跟岗演练
4. `READINESS_REVIEW`：独立上手前复核

### 4.3 实例化后的成员引导计划

- `onboarding_assignments`
- `onboarding_stage_progress`
- `onboarding_task_progress`

说明：
- 模板是静态定义
- Assignment 是给具体成员实例化后的执行面
- 以后转岗时可以重开新的 assignment，而不是覆盖原记录

### 4.4 导师与协作关系

- `mentor_links`
- `mentor_feedback_logs`

说明：
- 导师关系是引导过程对象，不等于组织汇报线
- 可以允许 1 个主导师 + 多个协作人

### 4.5 试用期里程碑与评审

- `probation_milestones`
- `onboarding_reviews`

说明：
- 里程碑是节点评审，不是考试结果
- 真正的模拟考 / 正式考结果由 `F026` 承接

---

## 5. 核心流程

### 5.1 到岗开局

1. `F011` 完成成员归属、部门、角色、销售空间挂接
2. 经理或运营为成员指定一个培养岗位路径
3. 系统按当前发布模板实例化一份 `onboarding_assignment`
4. 自动挂接导师与默认里程碑
5. 可选调用 `F018/F019` 生成阶段提醒

### 5.2 日常推进

1. 成员完成阶段任务
2. 导师确认演练项
3. 经理查看阶段完成度
4. 阶段达标后推进到下一阶段

### 5.3 转岗重开

1. 组织侧发生岗位调整
2. `F024` 不改组织关系，只新开一个新的岗位路径 assignment
3. 可复用已完成的公共任务
4. 与新岗位不兼容的任务重新开始

### 5.4 试用期复核

1. 系统汇总阶段任务和导师反馈
2. 经理做通过 / 打回 / 延长判断
3. 通过后可进入 `F025/F026` 后续能力面

---

## 6. 状态机

### 6.1 成员引导计划状态

```text
NOT_STARTED -> ACTIVE -> READY_FOR_REVIEW -> PASSED
                    \-> REWORK ------------^
                    \-> CLOSED
```

状态含义：
- `NOT_STARTED`：已分配但未启动
- `ACTIVE`：进行中
- `READY_FOR_REVIEW`：阶段任务已完成，等经理判断
- `PASSED`：当前岗位引导通过
- `REWORK`：打回补做
- `CLOSED`：因转岗、中止、离岗而关闭

### 6.2 任务状态

```text
PENDING -> IN_PROGRESS -> DONE
        \-> WAIVED
        \-> BLOCKED
```

说明：
- `WAIVED` 只用于明确免修项
- `BLOCKED` 用于等待外部条件，不等于失败

---

## 7. 默认任务包建议

`F024` 先锁任务包结构，不锁死最终内容条目。

### 7.1 基础认知包
- 公司与业务基本盘
- 销售流程与术语
- 合规与风险红线
- 工具与系统入口

### 7.2 产品认知包
- 产品线概览
- 标准报价逻辑
- 合同审核协作方式
- 常见案例阅读

### 7.3 跟岗演练包
- 跟听客户沟通
- 跟看报价编制
- 跟看合同澄清
- 场景演练记录

### 7.4 独立上手前复核包
- 必修项是否完成
- 导师意见是否齐备
- 经理是否确认进入下一阶段

## 8. 与其他 REQ 的边界

| 功能 | 拥有者 |
|------|--------|
| 组织树、成员归属、权限角色 | `F011` |
| 引导模板、岗位路径、阶段任务、导师规则 | `F024` |
| 胜任力项、学习内容映射、题库生产 | `F025` |
| 模拟考 / 正式考 / 补考、评分归档 | `F026` |
| 日程实例、提醒规则、提醒发送 | `F018 / F019` |

这条边界非常关键。

否则很容易把“岗位权限”“学习内容”“考试安排”“试用期评审”搅成一个大页签，最后对象不清、职责也不清。

---

## 9. 数据建模原则

推荐强类型对象：
- `role_paths`
- `role_path_versions`
- `onboarding_templates`
- `onboarding_assignments`
- `onboarding_stage_progress`
- `onboarding_task_progress`
- `mentor_links`
- `onboarding_reviews`

关键原则：

1. **模板与实例分离**  
   不能直接在成员执行记录上改模板定义。

2. **岗位路径与权限角色分离**  
   可以映射，不可复用同一张表直接顶替。

3. **转岗不覆盖历史**  
   应新开 assignment，历史记录继续保留。

4. **评审结论与考试结论分层**  
   `F024` 只处理引导阶段复核，不承担最终考试结果。

## 10. 客户端能力要求

### 10.1 新成员端
- 当前岗位路径卡片
- 当前阶段任务清单
- 里程碑时间线
- 导师信息

### 10.2 经理端
- 为成员指定岗位路径
- 查看阶段推进状态
- 通过 / 打回 / 关闭
- 查看导师反馈摘要

### 10.3 运营配置端
- 维护岗位路径模板
- 维护引导模板版本
- 设置默认导师规则
- 查看模板启用状态

注意：
- 页面文案使用“岗位成长 / 学习任务 / 阶段复核”等表达
- 不直接把内部的完整任职边界作为前台文案
