## 1. 设计原则

### 1.1 核心原则

| 原则 | 说明 |
|------|------|
| **规则柔性化** | 规则有 3 级阈值（下限 / 建议区间 / 红线），超出建议区间 = 强提醒，到红线才阻塞 |
| **多套可重叠** | 同一维度的多套规则集范围可重叠（按金额/客户类型/场景自动选） |
| **判不出 = 无效** | 授权版本（买断/订阅 × 公有云/私有部署）判不出 → 合同无效（强阻塞） |
| **变体识别** | 客户合同用 "Enterprise" 等替代词 → AI/NLP + 1.2 万词变体词典识别 |
| **ONES 仅作参考** | 不照搬 ONES skill 结构，只借鉴思路（单可信源、三表模型、二次验证） |
| **配置驱动** | 规则、模板、AI 降级策略全部在 UI 配置，不写死在代码 |
| **规则保存即生效** | 点击保存确认 → 立即生效（写审计日志） |
| **强提醒在报告内** | 不发外部通知（飞书/钉钉/邮件/站内信） |
| **知识库 Notion 化** | 树状、6+ 层、富文本 blocks、页面级权限 |
| **12 模板 + 12 规则直接导入** | 不让用户手动填，从 ONES skill 导入 |
| **权限点隔离** | 定义权限点 → 在权限点上加人，不直接配人 |

### 1.2 ONES skill 借鉴（不照搬）

ONES `ones-contract-assistant` skill（v2.2.2）是**参考**而非照搬：

| 借鉴 | 不照搬 |
|------|--------|
| 15 条款速查表的单一可信源原则 | SKILL.md 自由发挥的 agent 模式 |
| 三表模型（预览/澄清/摘要） | 品类分流的硬规则（我们要柔性） |
| 二次验证 6 项 | "默认最严格"判品类的硬逻辑（我们要"判不出=无效"） |
| 报告头固定格式 | 让步梯度的"必须换对价"硬约束 |
| 模板选择逻辑 | 多模型适配器架构 |
| eval 回归测试 | evals.json 评测集 |

### 2.5 状态机

| 状态 | 用户感知 | 进度条 | 操作按钮 |
|------|---------|--------|---------|
| **PENDING** | 合同已上传，等待审核 | 灰色圆点 | [开始审核] |
| **PARSING** | 正在解析合同文本... | 蓝色动画 0-20% | 刷新(禁用) |
| **ANALYZING** | 正在 AI 审核分析... | 蓝色动画 20-80% | 刷新(禁用) |
| **ASK_GENERATED** | 审核完成，生成 N 项待确认问题 | 蓝色 80% | [查看 ASK 清单] |

| **ASK_ALL_RESPONDED** | 全部问题已回应，可导出报告 | 绿色圆点 | [导出批注] |
| **COMPLETED** | 审核完成，报告已归档 | 绿色 ✅ | [查看历史报告] |
| **FAILED** | 审核失败，请重试 | 红色 ❌ | [重新审核] |

## 3. 合同审核主流程

### 3.1 完整链路

```
[第 1 层：规则维护层] (法务操作)
    ├─ 结构化规则 ──→ 12 条核心规则（柔性化阈值）
    └─ 语义规则 ────→ 留作扩展

[第 2 层：规则加载层] (系统后台)
    └─ 当前生效规则集 + 变体词典（1.2 万词）

[第 3 层：合同摄入层]
    ├─ 用户上传 Word/PDF
    ├─ OCR 解析（PDF/扫描件）
    └─ 文本提取 + 位置映射

[第 4 层：品类分流层]
    ├─ 变体识别（AI + 词典）
    ├─ 强阻塞：判不出 = 合同无效
    └─ 模板自动选择（12 模板）

[第 5 层：AI 降级层]
    ├─ Layer 1 本地 LLM
    ├─ Layer 2 云端 LLM
    ├─ Layer 3 规则引擎（保底）
    └─ Layer 4 人工补判

[第 6 层：执行层]
    ├─ 规则引擎扫描（确定性）
    └─ AI 语义分析（灵活性）

[第 7 层：结果聚合层]
    ├─ 合并 + 去重
    ├─ 风险分级（红/黄/绿）
    ├─ 二次验证 6 项
    └─ 三表生成

[第 8 层：输出层]
    ├─ 报告三 Tab（页面内）
    ├─ .md 下载
    └─ .docx 下载（带批注）
```

### 3.2 文档摄取（OCR）

| 格式 | 解析方式 | 适用 |
|------|---------|------|
| Word (.docx) | mammoth.js 提取文本+位置 | 主合同、附件 |
| PDF | pdf-parse 文本 + pdf2pic 图片 | 招标文件、扫描件 |
| 图片 (JPG/PNG) | PaddleOCR 本地识别 | 手机拍照件 |

**OCR 降级**：OCR 精度不足时保留原始文本，人工复核入口

### 3.3 基础信息结构化

```
合同主体（甲方乙方）
  ├─ 工商注册全称
  ├─ 统一社会信用代码
  ├─ 注册地址
  └─ 法人代表

合同金额
  ├─ 数字 + 大写
  ├─ 含税/不含税
  └─ 税率（13% 软件 / 6% 订阅）

合同时间
  ├─ 签约日期
  ├─ 生效日期
  └─ 终止日期

品类（自动判定 + 变体识别）
  ├─ 买断 / 订阅
  ├─ 公有云 / 私有部署
  └─ 新签 / 续约 / 增购
```

## 4. 配置中心规则设计（柔性化 3 级阈值）

### 4.1 规则分类

```
规则分类体系：
├── 结构化规则 (Structured Rules) - 100% 精确，毫秒级
│   ├─ 数值比较（账期 > 90 天）
│   ├─ 百分比比较（违约金 > 5%）
│   ├─ 文本包含/不包含
│   ├─ 正则匹配
│   ├─ 存在性检查
│   ├─ 日期比较
│   └─ 长度检查
│
└── 语义规则 (Semantic Rules) - AI 灵活理解
    └─ 自然语言描述的风险判断
```

### 4.2 柔性化 3 级阈值（核心）

每条规则有 3 个阈值：

```
规则：付款节奏
├─ 下限（强提醒）         30%         ← 低于此标黄，AI 解释让步空间
├─ 建议区间（绿灯）       30% - 100%  ← 在此区间直接通过
└─ 红线（强阻塞）         < 25%       ← 触达必须修改，不能签字
```

**多套规则集可重叠**（用户原话：可以有"15 到 30"这种重叠）：

```
规则集【严格-默认】付款节奏：下限 30% / 红线 <25%
规则集【宽松-战略】付款节奏：下限 15% / 红线 <10%
```

### 4.3 12 条核心规则（ONES 15 条款 + 用户决策）

| # | code | 名称 | 类别 | 关键阈值（默认值，可调） |
|---|--------|------|------|---------------------|
| 1 | PAYMENT_SCHEDULE | 付款节奏 | payment | 下限 30% / 建议 30-100% / 红线 <25% |
| 2 | EARLY_TERMINATION_REFUND | 终止退款 | termination | 不退款 / 仅退未消耗 / 全额退款 |
| 3 | TAX_RATE | 税率 | tax | 软件 13% / 订阅 6% / 错套红线 |
| 4 | DEFAULT_ACCEPTANCE_PERIOD | 默示验收期 | acceptance | 5 工作日 / 7-15 日 / >30 红线 |
| 5 | ACCEPTANCE_FAILURE | 验收不通过 | acceptance | 整改重交 / 2 次后解除 / 直接解除红线 |
| 6 | LIQUIDATED_DAMAGES | 违约金 | breach | 上限 ≤50% / 50-100% 警示 / >100% 红线 |
| 7 | CONSEQUENTIAL_LOSS | 间接损失 | liability | 明确排除 / 需补 / 承担间接红线 |
| 8 | LIABILITY_CAP | 责任 Cap | liability | ≤50% / 50-100% / >100% 红线 |
| 9 | CONFIDENTIALITY_PERIOD | 保密期 | confidentiality | 5 年 / 3-7 年 / 单向/永久红线 |
| 10 | PARTY_AND_AMOUNT | 主体·收款·金额 | general | 全对 / 旧版模板 / 错主体红线 |
| 11 | IP_OWNERSHIP | IP 归属 | ip | ONES 保留 / 二次开发让 / 客户主张红线 |
| 12 | DATA_SECURITY | 数据安全 | data | 客户所有 / 加密本地化 / AI 训练无授权红线 |
| 13 | SLA | SLA | service | 公有云 99.5% / 99.9% 评估 / 承诺可用性红线 |
| 14 | RENEWAL | 续约 | subscription | 书面 / 自动续期+通知 / 永久锁价红线 |
| 15 | DISPUTE_RESOLUTION | 争议解决 | general | 深圳 SCIA / 北京上海 / 境外红线 |

**实际导入 15 条全部，UI 隐藏 3 条作为备选**。

### 4.4 规则适用场景自动选择

| 维度 | 配置项 | 默认 |
|------|--------|------|
| 合同金额 | ≥ 50万 → 严格；< 50万 → 宽松 | 严格 |
| 客户类型 | 战略 / 大客户 → 宽松；普通 → 严格 | 严格 |
| 业务场景 | 新签 → 严格；续约/增购 → 宽松 | 严格 |
| 销售负责人 | 高级销售 → 宽松；初级 → 严格 | 严格 |

### 4.5 结构化规则配置示例

```yaml
- rule_code: PAYMENT_SCHEDULE
  name: 付款节奏
  rule_type: structured
  category: payment
  condition:
    field: first_payment_ratio
    operator: ">="
    value: 30
  # 3 级阈值（柔性化）
  threshold_lower_bound: 30          # 强提醒
  threshold_recommended_min: 30       # 建议区间最小
  threshold_recommended_max: 100      # 建议区间最大
  threshold_red_line: 25              # 红线
  threshold_unit: percent
  # 让步梯度
  concession_gradient:
    - {from: 'A', to: 'B', tradeoff: '缩短尾款账期至 15 天'}
    - {from: 'B', to: 'C', tradeoff: '增加履约保函'}
  # 话术
  scripts:
    - {scenario: '客户要求 100% 验收后付款',
       text: 'ONES 在项目前期会投入账号授权、实施工程师、技术支持等硬性成本，100% 验收后付款对我们来说资金压力较大...'}
  # 审批角色
  approval_roles: [法务, 财务]
```

## 5. 规则版本管理

### 5.1 版本链模型

每条规则有完整版本历史：

```
RULE-001 付款节奏 版本链：
v1.0 (2026-06-01) · 创建 · "下限 30% / 建议 30-100% / 红线 <25%"
  │
  ▼
v1.1 (2026-06-10) · 更新 · "下限调整为 35%"
  │
  ▼
v1.2 (2026-06-15) · 回滚 · "回滚到 v1.0"
```

### 5.2 版本操作

| 操作 | 说明 |
|------|------|
| 查看版本历史 | 显示所有历史版本 |
| 版本对比 | 显示两个版本之间的字段差异 |
| 回滚到版本 | 创建新版本（内容=目标版本快照） |
| 发布当前版本 | 标记为生效版本 |

### 5.3 生效机制

- **点击保存确认 → 立即生效**（用户已确认）
- 写 `contract_rule_audit_logs` 审计
- 生效后立即影响后续合同审核
- 已开始的合同不受影响（按上传时规则快照）

## 6. 规则测试沙箱

### 6.1 测试用例管理

- 规则可输入测试文本验证
- 返回触发结果（triggered / extracted_value / level）
- 与预期对比（pass / fail）
- 发布前必须跑回归测试

### 6.2 测试流程

```
单规则测试：
1. 选择规则 → 输入测试文本
2. 系统执行规则引擎
3. 返回结果（triggered、extractedValue、executionTime）
4. 用户对比预期 vs 实际

批量测试：
1. 选择多条测试用例
2. 系统逐条执行
3. 生成测试报告（通过率、失败列表、性能）
```

### 6.3 回归测试

规则变更前必须跑所有关联测试用例，失败阻止发布。

## 7. 规则命中率统计

### 7.1 统计指标

| 指标 | 定义 | 意义 |
|------|------|------|
| **触发率 (Hit Rate)** | 触发次数 / 总评估次数 | 规则有效性 |
| **触发趋势** | 触发率随时间变化 | 规则效果变化 |
| **平均执行时间** | 规则执行耗时 | 性能监控 |
| **风险分布** | 触发后 level 分布 | 规则严重程度 |

### 7.2 告警机制

| 告警 | 阈值 | 动作 |
|------|------|------|
| 低命中率 | < 10% 且评估 > 50 | 飞书通知管理员 + 标记待审核 |
| 高命中率 | > 80% | 飞书通知管理员（可能过宽） |
| 性能异常 | 平均 > 5000ms | 飞书通知技术 |

> **注意**：在合同审核中"强提醒"只在报告内显示，不发飞书通知（用户决策）。

## 8. 条款审核工作台

### 8.1 律师视角流程


## 12. 变体词典（1.2 万词）

### 12.1 用途

客户合同用替代词表达授权版本时，AI 自动识别：

| 标准术语 | 常见变体 |
|---------|---------|
| 私有部署 | Enterprise / On-Premise / 本地化部署 / 客户机房 / 自建机房 |
| 公有云 | SaaS / Cloud / 云端 / ONES 云 / 阿里云 / 华为云 |
| 买断 | 永久授权 / 一次性购买 / 买断式 / 永久许可 |
| 订阅 | 按年付费 / 年费 / 订阅式 / 年订阅 / 续费 |
| 增购 | 增售 / 升级 / 加量 / 增加账号 |
| 续约 | 续签 / 续订 / 续费 / 延期 |

### 12.2 1.2 万词组成

- 部署形态变体：~2,000 词
- 授权模式变体：~2,000 词
- 产品名称变体：~3,000 词
- 行业术语：~2,000 词
- 法律术语：~1,500 词
- 财务术语：~1,000 词
- 其他：~500 词

**1.2 万词用 ONES skill 推导**（用户决策）。

### 12.3 识别流程

```
合同文本 → 抽取关键短语 →
  ├─ 1. 查变体词典（精确匹配）
  ├─ 2. LLM 推理（变体识别）
  └─ 3. 标记品类/部署/授权模式
```

### 12.4 强阻塞（Q5 答案）

**判不出授权版本 = 合同无效**（不是 ONES 那种"默认最严格"）。

## 17. 权限模型（按权限点）

### 17.1 核心原则

> 用户原话："肯定是按权限点隔离，而不是说直接配到人身上"
> "由权限点定义隔离规则，然后再在权限点上面去加人"

### 17.2 权限点

```
权限点（Permission Point）
├─ 合同管理员
│  ├─ 范围：所有合同
│  ├─ 操作：增删改查 + 规则配置
│  └─ 数据隔离：无
├─ 合同审核员
│  ├─ 范围：本部门合同
│  ├─ 操作：审核、批注
│  └─ 数据隔离：按部门
├─ 销售
│  ├─ 范围：自己负责的客户合同
│  ├─ 操作：上传、查看自己客户的报告
│  └─ 数据隔离：按销售空间
├─ 财务审核员
│  ├─ 范围：所有财务相关合同
│  ├─ 操作：审核财务条款
│  └─ 数据隔离：按合同类型
├─ 知识库管理员
│  ├─ 范围：所有知识库
│  ├─ 操作：增删改查
│  └─ 数据隔离：无
└─ 知识库阅读员
   ├─ 范围：所有知识库
   ├─ 操作：查看
   └─ 数据隔离：按个人授权
```

### 17.3 权限点设计

```sql
CREATE TABLE permission_points (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code TEXT NOT NULL UNIQUE,         -- 'CONTRACT_ADMIN'、'CONTRACT_REVIEWER'
  name TEXT NOT NULL,
  description TEXT,
  scope JSONB DEFAULT '{}',          -- {resources: [...], actions: [...], filters: [...]}
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE user_permission_assignments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id),
  permission_point_id UUID NOT NULL REFERENCES permission_points(id),
  org_id UUID NOT NULL REFERENCES organizations(id),
  assigned_by UUID REFERENCES users(id),
  assigned_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, permission_point_id, org_id)
);
```

### 17.4 简化版 → 完整版演进

| 阶段 | 能力 |
|------|------|
| 简化版 | 权限点 + 资源级 ACL |
| 完整版 | 字段级权限 / 条件权限 / 审批流 |

## 23. 验收标准

### 23.1 核心功能

| TC | 场景 | 预期 |
|----|------|------|
| TC-01 | 销售上传合同 | 看到进度条 + AI 降级状态条 + 报告三 Tab |
| TC-02 | 法务查看合同详情 | 看到风险统计 + 效力分析 + ASK 清单 |
| TC-03 | 财务录入回应 | 只看到财务相关 ASK，录入后触发报告升版 |
| TC-04 | 管理员新增规则 | 选择结构化/语义 + 配置 3 级阈值 + 测试 + 保存即生效 |
| TC-05 | 规则测试沙箱 | 输入测试文本 → 返回触发结果 → 对比预期 |
| TC-06 | 规则版本回滚 | 选择历史版本 → 回滚 → 生成新版本 |
| TC-07 | 规则命中率统计 | 查看触发率 + 趋势 |
| TC-08 | 变体识别 | "Enterprise" 自动识别为私有部署 |
| TC-09 | 强阻塞（Q5） | 判不出授权版本 → 报告"合同无效" |
| TC-10 | 知识库 Notion 化 | 树状导航、6+ 层、富文本编辑、版本历史 |
| TC-11 | 12 模板 + 12 规则导入 | 全部直接可用，UI 可调整 |
| TC-12 | AI 降级显化 | 合同详情页显示 4 层状态条 |
| TC-13 | 权限点隔离 | 销售看不到其他销售的合同；财务只看财务相关 |

1. 位置引用核查
2. 原文摘要核查

4. 风险描述核查

6. 引申发散核查

- ❌ 不显示 token 用量
- ❌ 不做多版本对比（单版本先）
- ❌ 不做字段级权限（简化版先）
