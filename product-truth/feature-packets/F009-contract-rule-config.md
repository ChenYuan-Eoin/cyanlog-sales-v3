## 1. 单元定义

**目标**：让配置中心的合同审核规则成为生产规则源头。规则必须可以被人看懂、维护、测试、发布，并能生成审核引擎消费的规则包。

本功能不是让用户填写一堆难懂表单，也不是把 Markdown 黑盒丢给 AI 解析。正确形态是：规则库树管理规则资产，规则详情结构化表达机器可执行逻辑，AI 只负责辅助转译、补全和解释。

---

## 2. 业务骨架

### 2.1 三层对象

| 层级 | 对象 | 说明 |
|---|---|---|
| 规则库 | Rule Library | 一个业务规则资产库，例如“合同审核规则库” |
| 规则集 | Rule Set | 一个可发布的规则列表，例如“验收与交付规则集” |
| 规则项 | Rule Item | 可执行或可转译的单条规则，例如“默认验收期” |

当前阶段 UI 可以把“规则库”和“规则集”合并展示为树，但数据语义必须保留：规则集发布后才能被合同审核消费。

### 2.2 规则生命周期

```
草稿规则 -> 结构化配置 -> 测试通过 -> 发布版本 -> SkillBundle/EngineBundle -> 合同审核只读消费
```

单次合同审核不选择规则集版本。审核运行只读取配置中心当前已发布版本，并在 ReviewRun 中记录规则版本和 SkillBundle。

---

## 3. 页面目标

### 3.1 左栏：规则库树

- 支持搜索规则库、规则集、规则名称。
- 支持新建规则库、新建规则集、新建规则。
- 节点 Hover 显示设置和删除入口。
- 选中规则后直接显示规则详情，不再出现无意义的中间大卡片。

### 3.2 右栏：规则详情

规则详情只保留能驱动机器执行和人类理解的字段：

| 区域 | 字段 |
|---|---|
| 标识 | 置灰 ID、规则名称、状态、版本 |
| 触发条件 | 关键词定位、语义触发、字段/数值触发、适用范围 |
| 判定器 | 条件表达式、红/黄/绿等级、例外条件 |
| 证据要求 | 必须定位的原文、source range 要求、不可定位处理 |
| 输出动作 | 通过、进入谈判、风险批注、阻断、人工复核 |
| 测试规则 | 模拟合同文本或结构化字段，返回是否命中和等级 |

### 3.3 禁止项

- 不用大段“给人看的说明”冒充机器规则。
- 不把“修改建议”作为人工阅读字段堆给用户；它应是 AI/引擎输出动作的一部分。
- 不把触发器、判定器、输出模板混在一个长表单里。
- 不让未发布规则进入正式审核。

---

## 4. 与 AI 的关系

AI 在 F009 中承担辅助角色：
- 把声明式规则转译为结构化 RuleUnit。
- 解释规则命中原因。
- 生成测试样例。
- 生成批注草案。

AI 不拥有规则源头。规则源头是配置中心发布版本。

---

## 5. 验收标准

- [x] 规则库树支持规则集、规则项的新增、查询、编辑、归档；当前产品 UI 将规则库与规则集合并为同一导航层，数据层保留 Rule Set 语义。
- [x] 点击规则项后直接进入结构化详情；详情使用分区和 Tab 控制信息量，不再经过无意义中栏。
- [x] 触发条件、判定器、证据要求、输出动作结构化可维护。
- [x] 测试规则能返回命中结果、风险等级、调用模型或确定性执行证据以及失败原因。
- [x] 发布事务生成规则集快照和 SkillBundle / EngineBundle，并递增发布版本。
- [x] ReviewRun 记录并展示规则发布版本和 SkillBundle 证据。
- [x] 发布必须存在晚于规则最后修改时间的通过 eval；未通过测试或存在歧义的规则不能进入新正式包。
