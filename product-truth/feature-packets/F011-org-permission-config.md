# Feature Packet: F011-组织权限配置

**Created**: 2026-06-09  
**REQ ID**: F011  
**Status**: confirmed  
**Parent**: 配置中心  
**Depends On**: `F000-config-center-architecture`

---

## 1. 单元定义

**目标**：在配置中心维护组织基础面和访问控制面，让 `F003` 的鉴权执行、`F004` 的审批执行、`F002` 的报价数据范围都有稳定配置来源。

`F011` 必须分成两个子面理解，而不是做成一个“角色勾权限”的页面：

### 1.1 组织架构管理
- 部门树
- 成员档案
- 主部门 / 兼职部门
- 部门数据范围
- 外部通讯录同步入口（如飞书）

### 1.2 角色权限管理
- 角色定义
- 角色拥有的业务能力
- 角色的数据范围 / 作用域
- 成员与角色分配
- 审批代理 / 转交范围等组织策略

**这包不拥有的内容**：
- 登录、发 token、会话校验
- 中间件鉴权执行
- 报价或合同的具体审批动作
- 合同审核规则内容

这些分别属于 `F003 / F004 / F009`。

## 3. 配置对象

### 3.1 组织架构管理对象
- 部门层级
- 人员归属
- 上下级关系
- 部门归属和可见范围
- 外部源同步状态

### 3.2 角色权限管理对象
- 系统预置角色
- 自定义角色
- 角色与业务能力关系
- 角色分配成员
- 角色分配作用域

### 3.3 数据范围
- `OWN`：仅本人
- `DEPT`：指定部门。授权范围可明确包含下级部门。
- `SPACE`：历史绑定标识。现行部门授权使用 `DEPT`。
- `ORG`：全组织

### 3.4 审批组织策略
- 代理人设置
- 转交范围
- 升级链可见范围

### 3.5 部门与数据范围

- 每个启用部门就是一个可选数据范围，选项使用组织架构中的部门 ID。平台超管可在当前有效组织选择获授权的部门。新部门随组织树进入选项，名称、层级和可见性在改名、改隶、停用和重新授权后重新计算。
- Team Leader 的数据范围按该动作的有效权限计算，可包含多个授权部门及下级。工作台提供「授权范围汇总」「仅本部门」「含下级部门」三种视图，并按当前授权取交集。华南负责人可以选授权内的大部门和小部门，公司同层的未授权平台部不显示，也不能直接查询。重叠部门和成员分别去重。
- 既有业务记录通过原关联键追溯所属部门。历史记录关联用于兼容读取，现行选择和授权均来自当前部门树。既有空间绑定继续可核对和撤销。
- 查看部门成员使用已生效的权威目录，包含同步在职但尚未登录的员工。部门树统计含下级，部门名单按当前所选范围取数。目录不可核对时显示未核实状态，历史成员和本地成员通过对应筛选查看。

### 3.6 角色人数、保存和超管任命

- 角色列表和详情通过角色 ID 与有效作用域核对同一份数据。已生效成员、待生效成员、有效绑定分别统计；一名成员的多个有效绑定只计一名。待生效成员以服务端确认的首次登录预分配为准。
- 保存角色权限时校验当前组织、角色和原授权快照，并回读保存结果。超级管理员任免在目录中登记为一个受保护动作。在组织绑定批次中，两个入口统一到唯一的「超级管理员」角色，并保留指定系统账号的保护规则。

### 3.7 当前权限整改的业务验收

按 `IN-20261126-002`，业务配置保存与授权保存各自校验。经营参数、填写规则、月结与服务、连接设定等业务配置由获得相应权限的人员使用。只有系统超管可以配置部门权限、角色权限、个人权限差异、角色成员和数据范围，以及任免超管。有效部门成员可继承超管已明确配置的部门权限。目录同步、首次登录和业务角色名称本身不发放业务权限。

首批验证寄件填写规则及角色授权的写入边界。侧栏「寄件设置」和配置中心「寄件配置」使用同一业务配置入口。公司名称填写规则归业务配置，部门提报资格归组织授权。角色定义、普通角色分配和作用域的写入一并核验系统超管资格。目标回归覆盖业务配置人员可以修改填写规则、不能修改提报资格，以及超管可以单独保存资格和角色授权。

系统超管任免使用现有的系统超管角色。账号可登录、在默认组织有效在职、并持有该组织的系统超管绑定时，按系统固定定义生效。历史角色权限覆盖不改变系统超管定义。系统超管可以任免本组织其他符合条件的成员，变更须核对原状态并独立回读。停用登录、离职、移出组织和撤销超管须共用最后一名有效超管保护。外部目录更新在职状态时也须遵守此规则。普通角色分配和邀请入口不能授予超管。历史组织治理授权由系统超管核对和撤销，既有持有人不自动升为系统超管。

角色权限保存、成员与作用域的普通角色分配、邀请角色预分配和寄件提报部门资格，写入时在同一组织事务中重新核验系统超管身份。业务参数的独立接口继续核验对应业务动作及配置版本。

纷享登录保留身份和在职校验。激活只落实超管此前预分配的角色及为同一条已核验身份保存的个人差异。无授权人员登录后进入待授权页，可以查看本人信息、退出，或在同一会话检查管理员的新授权。业务菜单和业务接口继续按授权开放。

历史纷享基础角色停止新增分配、停止编辑定义，旧绑定不产生业务权限。已有成员绑定仍可核对和撤销。整组保存如果保留既有历史绑定，发放人和时间保持原样。旧记录仅凭当前发放人、授予时间或无增量的整组保存无法证明明确发放，需对照同组织的历史授权事件。

普通角色的本人寄件动作来自系统超管已保存的本人权限；寄件连接管理也须明确授予。本人单据继续按所有者和当前组织校验，历史回执须有本人查看或台账查看，且匹配原回执码和组织。

「查看收寄台账」是首个接入部门数据范围的权限点。部门与角色分别使用同一权限表明确配置。有权查看台账的人员按该动作的数据范围选择部门。存量台账授权中的「含下级部门」用于记录范围。无法核验部门归属的历史工单继续由具有全组织查看权限的人读取。本人提报、工单审批、物流刷新和业务参数修改各自校验授权。

权限表的寄件入口状态取自已登记、已发布且可执行的动作。勾选已发布动作时一并补齐其查看权限。关闭寄件入口清除本模块的授权草稿，保留其他模块权限。配置中心入口由实际可访问的标签决定，权限表、侧栏和页面共用同一判定。仅获部门台账权限时，侧栏显示对应业务入口；独立的部门工作台权限另行生效。

同一「组织与权限」页面提供组织架构、外部系统接入和角色权限三个入口。系统超管可以在当前组织创建空权限的普通角色、改名和删除。既有共享角色在当前组织覆写名称、说明和权限，角色标识及其他组织的配置独立保存。删除前先解除当前组织的成员分配、待生效授权和未完成的邀请，后台归档保留历史关联。角色元数据提交时核对组织和角色修订版本。

组织管理、成员、部门和角色目录按保存的权限判断。历史组织治理角色的绑定保留以便审核和撤销，不再产生运行权限。外部接入按连接状态、连接维护、目录预览和同步应用分别校验。只获连接维护授权时可以校验凭据、读取连接状态；目录预览只对获得预览权限的人返回。企业登录开关由当前组织的系统超管修改。

仅有角色目录读取授权时直接打开角色列表；员工目录在已获相应权限时读取。只有部门工作台权限时，业务侧栏显示工作台。寄件工单处于下单结果待确认时，查回承运商结果独立校验查回权限。台账查看授权可读已保存指令，实时判断转寄或退回可用性另行校验对应操作权。

部门工作台、角色配置和寄件权限可以在同一会话中同时生效。对于仅有组织、配置或寄件授权的员工，侧栏仅显示已授权入口，直接访问未授权业务路径也会被拒绝。移除其中一项授权后，重新请求时只移除对应入口和请求权限。

权限字典按动作存储系统模块、能力层级和支持的数据范围。部门、角色、员工共用这份权限字典。基础授权按部门和角色对同一权限点取并集，最终按个人差异结果检查动作及其依赖。对象级协作、审批条件和字段显隐继续由各业务规则处理。

「退回工单」是独立的 L3 角色权限。台账查看与退回作用域按实际工单取交集。只有满足这两项范围且处于待审核状态的记录显示退回。新的退回权限登记后，旧核对授权不附加此动作。系统超管及具备组织级退回和查看授权的角色可处理本组织无部门归属的历史工单。

组织授权数据统一经受权限校验的服务端入口访问。数据库撤销 PUBLIC、anon 和 authenticated 对组织、部门、成员部门关系、成员角色和角色定义的直接访问，保留服务端操作与员工自己的画像读取。

后续按系统功能统一 L1–L4 的可授予权限点，将逐权限点计算范围应用到其他已接入动作。业务参数按各功能的实际职责配置。存量自动补发的权限在迁移前与超管对账确认。

日期栏三按钮保持独立候选及生产验收。其他业务模块的功能整改保留在各自的本地工作中。

### 3.8 唯一权限表与个人差异

- 按系统功能模块与 L1–L4 展示同一张权限表。新增权限点后，部门、角色、员工三种视图同步显示，生效仍由超管授权。从任一视图的成员名单点开同一员工时，展示其当前完整有效权限、基础授权来源及个人差异。部门名称用于组织选择与数据范围。
- 按权限点合并员工当前明确获得的部门与角色授权。多个来源的数据范围取并集，按当前组织树展开后去重。员工没有手工修改此点时，最终结果来自基础并集。
- 个人手工修改某权限点后，以保存的开关和数据范围直接覆盖这一项。个人可开启、关闭、扩大或缩小该点的数据范围。员工表在原权限点的范围字段设置范围。恢复默认删除该点的差异并使用当前基础结果。动作依赖使用最终结果校验。
- 个人只持久化手工调整的项，以当前组织、员工、权限点为唯一维度。开关与范围一起校验、保存及回读，记录变更人并审计前后值。系统超管的固定权限由专用规则处理。员工调岗或角色变动时提示已有差异，目录同步后可复核。
- 已核验且仍在职的纷享员工在首次登录前可由超管通过同一表预配置个人差异。表中显示当前部门和预分配角色计算出的结果，并标明待首次登录生效。预配置绑定同一已核验的目录身份，首次 SSO 完成该身份校验后才落实已保存的差异。成员菜单提供停用首次登录和办理 ICU 离职。
- 权限点的范围遵守动作支持的范围类型，按当前组织树解析部门及下级，继续执行同组织、记录归属和业务状态校验。侧栏、业务页的数据范围选择器、读取接口和写入事务使用最终结果。
- 首批验收用同一「查看收寄台账」验证部门与角色范围并集、个人缩小、扩大、关闭和恢复默认。同角色其他员工的结果分别计算。检查个人改动后的同会话请求、界面、记录读取、依赖动作及实际写入事务。
- 组织架构的查看成员、编辑成员、邀请、管理登录、管理在职、移出组织，以及查看部门树、维护部门、删除部门和查看角色及成员，共用同一员工权限表。个人覆盖采用当前组织范围。个人关闭优先于此前的角色组合授权，与之相关的查看依赖按员工最终权限校验。角色授权、任免超管等专用动作继续核对操作人的系统超管身份。
- 成员目录与部门树可分别授权。仅获成员查看时返回人员数据，隐藏部门结构、归属和作用域明细。仅获部门查看时返回部门结构，隐藏成员名单。变更后同一会话再次请求，以当前保存结果决定入口、读取和写入。

## 4. 与 F003 / F004 / F009 的边界

| 功能 | 拥有者 |
|------|--------|
| 用户登录 / token 签发 / session | `F003` |
| 权限中间件执行 | `F003` |
| 审批动作执行 | `F004` |
| 合同审核规则内容 | `F009` |
| 组织、角色、数据范围配置 | `F011` |

这条边界非常关键。

否则很容易把“合同规则”“组织架构”“权限校验逻辑”“审批流动作”混成一个模块，最后任何一处改动都会牵动整条链。

## 5. 数据建模原则

推荐强类型对象：
- `organizations`
- `departments`
- `users`
- `user_departments`
- `roles`
- `user_roles`
- `sales_spaces`
- `delegation_rules`

MVP 可以复用已有角色表，但必须保证：
- 组织配置可管理
- 菜单权限不是写死在前端
- 数据范围可被后端执行
- 作用域至少覆盖 `org / department / space`

这里有一个关键判断：

**后端权限键可以继续存在，但它只是执行码，不是产品模型本身。**

前台角色权限页必须按以下三层呈现：
1. 能访问哪些管理域 / 业务域
2. 能执行哪些业务动作
3. 数据范围落在哪些组织作用域

角色权限页可以使用三栏，但三栏必须形成权限闭环：

| 栏位 | 内容 | 验收标准 |
|------|------|----------|
| 左栏：角色列表 | 角色、成员数、作用域数、发布/保存状态 | 一眼看到角色资产和异常角色 |
| 中栏：权限矩阵 | 按业务域分组的权限点、动作、数据范围和继承来源 | 权限编辑密度高，避免把每个权限做成大卡片；可批量切换和搜索 |
| 右栏：闭环摘要 | 当前角色能访问什么、影响哪些成员和部门、是否可发布、需要刷新哪些上下文 | 能回答“这个角色实际会造成什么效果，以及下一步做什么” |

权限点展示必须优先使用矩阵、表格或紧凑列表。只有复杂策略说明、冲突说明、发布阻断和影响范围适合放到右栏卡片。不得把大量 checkbox 逐个做成宽松卡片，导致用户无法快速判断权限链条。

## 6. 客户端能力要求

### 6.1 配置中心前端

应拆成两个入口，不可混进合同规则：

#### A. 组织架构
- 组织树浏览
- 成员列表
- 部门层级和成员关系展示
- 外部通讯录同步入口
- 跳转真实组织后台

#### A.1 外部通讯录同步 MVP（飞书）

当前阶段承诺“飞书部门树、成员基础档案和主部门关系同步”。手机号、岗位、头像等字段在飞书返回且系统字段可承载时写入。汇报关系和角色分配单独维护，工作台直接使用当前部门树。

同步入口必须具备明确反馈，而不是只提供一个按钮：
- 未配置 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 时，前端必须展示“飞书同步未配置”、缺失项和下一步配置位置（Vercel 环境变量 / 本地 `.env.local`）。
- 同步成功时，前端必须展示部门新增/更新/失败/总数，以及成员新增/更新/跳过/失败/总数，并刷新组织架构摘要。
- 只拿到 root、0 个可访问部门、部门或成员局部失败时，必须显示“部分完成/失败原因”，不能展示为完整同步成功。
- 上游飞书接口失败时，接口必须返回可识别错误码和排障提示，前端必须展示失败原因。
- 文案必须明确“当前 MVP 同步部门、成员和主部门关系，不自动完成角色分配和完整通讯录治理”，避免把外部组织同步误解为权限体系已自动配置完成。

#### B. 角色权限
- 角色列表
- 业务能力分组展示
- 数据范围说明
- 角色绑定成员
- 角色绑定作用域
- 代理策略配置

### 6.2 业务前端
- 导航按权限展示
- 无权限时明确拒绝
- 列表按数据范围过滤

## 7. 当前实现判断

当前工程不是“完全没有组织权限能力”，而是**已有组织后台与作用域数据模型，但配置中心又额外做了一套简化版角色面板**。

已经存在的真实能力：
- `/api/admin/org`
- `/admin/org`
- `departments / user_departments / user_roles / sales_spaces`
- `scope_type = org / department / space`

当前错误点：
- 把“组织与权限”错误放进“治理与规则”
- 把权限模型做成一组裸露的后端动作码 checkbox
- 没有把已有 `admin/org` 的真实能力收回到配置中心信息架构

因此下一轮重点不是再造一套组织系统，而是：
1. 把信息架构改正
2. 把配置中心收口到真实组织后台能力
3. 用业务能力分组重表达角色权限

## 10. 组织与权限操作验收

组织架构、外部系统接入、角色权限提供三个入口。权限矩阵按系统功能和 L1–L4 展开。部门、角色和个人权限共用权限目录，勾选、保存回读和业务请求采用当前授权结果。业务参数在各功能设置页维护。

| 场景 | 操作与验收结果 |
| --- | --- |
| 组织成员 | 行菜单可分配角色、进入员工权限、停用或启用账号、办理离职。入口状态按当前操作权限、人员状态和超管保护计算。停用账号撤销 ICU 登录与会话，办理离职结束 ICU 成员身份及授权。外部人事系统仍维护其来源记录。 |
| 个人角色分配 | 勾选授予、取消勾选撤销。保存后重新打开核对选中项。组织级变更保留其他组织及部门作用域内的绑定。任命或撤销系统超管在同一角色流程中维护，变更限制由后端执行。 |
| 角色成员 | 可移除该角色的指定作用域绑定，或进入与组织架构共用的员工权限表。成员的其他角色和作用域继续保留。 |
| 人数与部门删除 | 同步在职按当前同步名单计数。当前筛选隐藏直属关联成员时提供名单入口。部门有成员关联时拦截删除并定位到该部门名单。 |
| 单选与部门全选 | 支持逐人勾选。全选覆盖当前部门范围与筛选结果的全部页。切换范围后清除旧选择，页面内刷新保留仍有效的选择。 |
| 批量操作 | 支持停用账号、办理离职、分配普通角色。逐名返回成功或失败。批量分配增加选中的角色，原有角色及数据范围继续保留。失败项可定位并重试。 |
| 操作后状态 | 点击菜单、切换部门和打开员工权限无整页重载。保存后更新目标列表并保留仍有效的部门、搜索和页码。 |
| 自助收寄 | 同一账号核对侧栏、部门选择范围、台账和实际动作；部门树调整后动态展开授权范围；同一员工个人权限可覆盖基础并集。 |

系统只保留一个固定定义的超级管理员角色。超管任免和账号操作保护最后一名有效超管。正式站验收核对精确发布提交、已有管理员会话和普通成员会话。
