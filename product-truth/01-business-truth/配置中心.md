## 1. 为什么配置中心是核心

配置中心是系统的"大脑"，所有业务规则在此集中管理：

- **合同审核规则**：决定合同审核的红绿灯判断逻辑
- **税率规则**：影响报价金额计算
- **审批权限配置**：决定折扣审批的流转路径

## 2. 配置分类

| 配置类型 | 用途 | 管理方 | 生效方式 |
|---------|------|--------|----------|
| 合同审核规则 | 红绿灯规则、语义规则 | 法务/管理员 | 发布后生效 |
| 税率规则 | 报价计算、合同金额 | 财务/管理员 | 发布后生效 |
| 审批权限配置 | 折扣审批、合同审批 | 管理员 | 发布后生效 |
| AI模型配置 | 模型连接参数 | 技术/管理员 | 保存后立即生效 |

## 3. 数据模型

```prisma
// 配置表
model Config {
  id          String   @id @default(cuid())
  key         String   @unique    // 配置键
  value       String              // 配置值（JSON格式）
  type        ConfigType          // 配置类型
  version     Int     @default(1) // 版本号
  status      ConfigStatus @default(DRAFT)
  description String?
  createdBy   String
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

enum ConfigType {
  CONTRACT_RULE    // 合同审核规则
  TAX_RULE         // 税率规则
  APPROVAL_RULE    // 审批权限配置
  AI_CONFIG        // AI模型配置
}

enum ConfigStatus {
  DRAFT     // 草稿
  PUBLISHED // 已发布
  ARCHIVED  // 已归档
}
```

## 4. 配置类型详细设计

### 4.1 合同审核规则配置（红绿灯规则）

```yaml
# 合同审核规则配置
rules:
  - id: "RULE-001"
    name: "付款账期检查"
    category: "financial"
    level: "red"
    condition:
      field: "payment_term_days"
      operator: ">"
      value: 90
    message:
      title: "账期超过90天"
      description: "当前账期为{extracted_value}天，超过标准90天"
      suggestion: "建议缩短至60天内或增加预付款比例"

  - id: "RULE-002"
    name: "违约金比例检查"
    category: "legal"
    level: "yellow"
    condition:
      field: "penalty_rate"
      operator: ">"
      value: 0.05
    message:
      title: "违约金比例偏高"
      description: "当前违约金比例为{extracted_value}，超过5%"
      suggestion: "建议协商降低至3%以内"
```

### 4.3 审批权限配置

```yaml
# 审批权限配置
approval_rules:
  discount:
    thresholds:
      - limit: 5
        approver: "auto"           # 5%以内自动通过
      - limit: 10
        approver: "sales_manager"  # 5-10%需销售经理审批
      - limit: 20
        approver: "sales_director" # 10-20%需总监审批

      - limit: 50000

        approver: "sales_director" # 20万以内总监审批
      - limit: 1000000

```

## 5. 配置版本与回滚

### 5.1 版本管理

```
配置变更流程：

保存草稿
    │
    ▼
测试验证（沙箱）
    │
    ▼
发布（创建新版本）
    │
    ▼
生效（影响新单据）
```

### 5.2 回滚机制

```typescript
interface ConfigVersion {
  id: string;
  configId: string;
  version: number;
  value: string;        // JSON格式
  createdBy: string;
  createdAt: Date;
  rollbackTo?: string;  // 回滚到哪个版本
}

// 回滚操作
async function rollbackConfig(configId: string, targetVersion: number) {
  const target = await ConfigVersion.findOne({
    configId,
    version: targetVersion,
  });

  if (!target) {
    throw new Error(`版本 ${targetVersion} 不存在`);
  }

  // 创建新版本（内容回滚到目标版本）
  await Config.create({
    configId,
    value: target.value,
    version: await getNextVersion(configId),
    status: 'PUBLISHED',
    rollbackTo: targetVersion,
  });
}
```

## 6. 配置变更流程

```
配置变更审批流程：

1. 配置编辑（管理员）
   ├── 编辑规则
   └── 保存草稿

2. 测试验证（测试人员）
   ├── 沙箱测试
   └── 验证通过

3. 发布审批（审批人）
   ├── 审批通过
   └── 发布生效

4. 监控观察（系统）
   ├── 异常检测
   └── 自动告警
```

## 7. API 接口

### 7.1 配置管理

| 方法 | 路径 | 描述 | 请求体 | 响应 |
|------|------|------|--------|------|
| GET | /api/configs | 配置列表 | Query: type, status | ConfigList |
| GET | /api/configs/:id | 配置详情 | - | Config |
| POST | /api/configs | 创建配置 | ConfigCreateDTO | Config |
| PUT | /api/configs/:id | 更新配置 | ConfigUpdateDTO | Config |
| DELETE | /api/configs/:id | 删除配置 | - | Success |
| POST | /api/configs/:id/publish | 发布配置 | - | Config |
| POST | /api/configs/:id/rollback | 回滚配置 | {version: number} | Config |
