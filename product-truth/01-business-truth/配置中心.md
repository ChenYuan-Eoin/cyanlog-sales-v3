## 1. 为什么配置中心是核心

配置中心是系统的"大脑"，所有业务规则在此集中管理。当前正式运行时以 `product-truth/product-code` 为准：

- **合同审核规则**：决定合同审核的红绿灯判断逻辑
- **税率规则**：影响报价金额计算
- **审批权限配置**：决定折扣审批的流转路径
- **AI 模型配置**：决定本地模型、销售云端模型、规则引擎的运行时路由
- **价盘与阶梯价**：决定 SKU、基础价、保护价、区间价

## 2. 配置分类

| 配置类型 | 用途 | 管理方 | 生效方式 |
|---------|------|--------|----------|
| 合同审核规则 | 红绿灯规则、语义规则 | 法务/管理员 | 发布后生效 |
| 税率规则 | 报价计算、合同金额 | 财务/管理员 | 发布后生效 |
| 审批权限配置 | 折扣审批、合同审批 | 管理员 | 发布后生效 |
| AI模型配置 | 本地模型、OpenAI 兼容云端模型、降级链 | 技术/管理员 | 发布后生效 |
| 价盘与阶梯价 | SKU、基础价、最低价、阶梯价 | 销售运营/管理员 | 发布后生效 |

## 3. 数据模型

```prisma
// 配置表
model Config {
  id          String   @id @default(cuid())
  key         String   @unique    // 配置键
  value       String              // 配置值（JSON格式）
  type        ConfigType          // 配置类型
  version     Int     @default(1) // 版本号
  status      ConfigStatus @default(DRAFT)
  description String?
  createdBy   String
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

enum ConfigType {
  CONTRACT_RULE    // 合同审核规则
  TAX_RULE         // 税率规则
  APPROVAL_RULE    // 审批权限配置
  AI_CONFIG        // AI模型配置
}

enum ConfigStatus {
  DRAFT     // 草稿
  PUBLISHED // 已发布
  ARCHIVED  // 已归档
}
```

## 4. 配置类型详细设计

### 4.1 合同审核规则配置（红绿灯规则）

```yaml
# 合同审核规则配置
rules:
  - id: "RULE-001"
    name: "付款账期检查"
    category: "financial"
    level: "red"
    condition:
      field: "payment_term_days"
      operator: ">"
      value: 90
    message:
      title: "账期超过90天"
      description: "当前账期为{extracted_value}天，超过标准90天"
      suggestion: "建议缩短至60天内或增加预付款比例"

  - id: "RULE-002"
    name: "违约金比例检查"
    category: "legal"
    level: "yellow"
    condition:
      field: "penalty_rate"
      operator: ">"
      value: 0.05
    message:
      title: "违约金比例偏高"
      description: "当前违约金比例为{extracted_value}，超过5%"
      suggestion: "建议协商降低至3%以内"
```

### 4.4 AI 模型配置

AI 配置不再只是环境变量，而是配置中心发布的组织级运行时策略。推荐形态：

```yaml
ai_profiles:
  - key: "AI_LOCAL_PRIMARY"
    level: 1
    profile: "local_primary"
    provider_kind: "openai_compatible"
    base_url: "http://localhost:1234/v1"
    model: "qwen3-32b"
    api_key: ""
    timeout_ms: 45000
    routing:
      max_pages: 15
      strategy: "full"
    enabled: true

  - key: "AI_SALES_CLOUD_BACKUP"
    level: 2
    profile: "sales_cloud_backup"
    provider_kind: "openai_compatible"
    base_url: "https://sales-model.example.com/v1"
    model: "gpt-4.1"
    api_key: "sk-***"
    timeout_ms: 20000
    routing:
      max_pages: 80
      strategy: "chunked"
    enabled: true

  - key: "AI_RULE_FALLBACK"
    level: 3
    profile: "rule_engine"
    provider_kind: "builtin"
    base_url: ""
    model: "rule-engine"
    timeout_ms: 1000
    enabled: true
```

约束原则：

- 本地模型可使用客户自有推理服务，只要提供 OpenAI 兼容接口
- 云端模型优先支持销售团队自有 OpenAI 兼容网关
- 合同审核、Ask、后续智能助手统一读取已发布 `AI_CONFIG`
- 前端允许编辑 API Key，但更新时必须支持“保留已有密钥”

### 4.5 价盘与阶梯价

价盘是配置中心拥有的控制面，报价中心只能读取，不允许在报价流程中改写 SKU 价格。

```yaml
price_book:
  products:
    - code: "PROD-001"
      name: "智能合同审核系统"
      specification: "企业版"
      unit: "套"
      base_price: 98000
      min_price: 80000
      tier_pricing_enabled: true
      status: "active"
      tiers:
        - qty_from: 1
          qty_to: 10
          unit_price: 98000
        - qty_from: 11
          qty_to: 50
          unit_price: 92000
        - qty_from: 51
          qty_to: null
          unit_price: 88000
```

落地要求：

- `products` 语义升级为 SKU 主表
- 阶梯价由 `product_price_tiers` 独立建模
- 价盘按组织隔离，必须带 `org_id`
- 报价创建时保存价格快照，避免后续价盘变更影响已生成报价

## 5. 配置版本与回滚

### 5.1 版本管理

```
配置变更流程：

保存草稿
    │
    ▼
测试验证（沙箱）
    │
    ▼
发布（创建新版本）
    │
    ▼
生效（影响新单据）
```

### 5.2 回滚机制

```typescript
interface ConfigVersion {
  id: string;
  configId: string;
  version: number;
  value: string;        // JSON格式
  createdBy: string;
  createdAt: Date;
  rollbackTo?: string;  // 回滚到哪个版本
}

// 回滚操作
async function rollbackConfig(configId: string, targetVersion: number) {
  const target = await ConfigVersion.findOne({
    configId,
    version: targetVersion,
  });

  if (!target) {
    throw new Error(`版本 ${targetVersion} 不存在`);
  }

  // 创建新版本（内容回滚到目标版本）
  await Config.create({
    configId,
    value: target.value,
    version: await getNextVersion(configId),
    status: 'PUBLISHED',
    rollbackTo: targetVersion,
  });
}
```

## 6. 配置变更流程

```
配置变更审批流程：

1. 配置编辑（管理员）
   ├── 编辑规则
   └── 保存草稿

2. 测试验证（测试人员）
   ├── 沙箱测试
   └── 验证通过

3. 发布审批（审批人）
   ├── 审批通过
   └── 发布生效

4. 监控观察（系统）
   ├── 异常检测
   └── 自动告警
```

## 7. API 接口

### 7.1 配置管理

| 方法 | 路径 | 描述 | 请求体 | 响应 |
|------|------|------|--------|------|
| GET | /api/configs | 配置列表 | Query: type, status | ConfigList |
| GET | /api/configs/:id | 配置详情 | - | Config |
| POST | /api/configs | 创建配置 | ConfigCreateDTO | Config |
| PUT | /api/configs/:id | 更新配置 | ConfigUpdateDTO | Config |
| DELETE | /api/configs/:id | 删除配置 | - | Success |
| POST | /api/configs/:id/publish | 发布配置 | - | Config |
| POST | /api/configs/:id/rollback | 回滚配置 | {version: number} | Config |
