## 1. 报价工作台定位

**报价工作台是独立完成报价流程的工作面，不是CRM的取数末端**。

补充边界：

- **价盘 / SKU / 阶梯价由配置中心维护**，报价中心只读消费已发布版本
- **税率 / 审批阈值 / AI 路由来自配置中心**，报价中心不直接写配置
- 当前正式运行时以 `product-truth/product-code` 为准

| 维度 | 报价工作台 | CRM关系 |
|------|-----------|---------|
| **核心职责** | 报价单全生命周期管理 | 客户数据来源/同步方 |
| **操作主体** | 销售在报价中心操作 | CRM系统维护客户主数据 |
| **数据流向** | 从CRM拉取客户信息 | 接收报价结果回写 |
| **Source of Truth** | 报价中心数据库 | CRM客户主数据库 |

### 1.1 字段归属原则

- **从CRM拉取**：客户名称、联系人、历史成交价、客户等级
- **工作台维护**：报价明细、折扣、税率、有效期、审批状态
- **双向同步**：客户基础信息变更时同步，报价状态变更时回写CRM

### 1.2 独立开局能力

- 报价中心可完全独立运行，不强制依赖CRM
- 支持快速录入客户（仅名称+电话），后续补全
- CRM离线时，报价中心仍可创建报价（标记为"待同步"）

## 3. 产品电路

### 3.1 输入层（多源数据源）

```
输入层
├── 客户信息（双路径）:
│   ├── CRM同步路径：选择客户 → 自动填充历史联系人/上次成交价
│   └── 快速路径：仅填客户名称+电话（30秒开单，信息后续补全）
│
├── 产品信息（配置中心价盘）:
│   ├── 基础价：SKU 标准价
│   ├── 阶梯价：按数量命中区间单价
│   └── 自定义行：仅限非标补充项，需保留人工录入痕迹
│
└── 折扣触发检测（自动审批流）:
    ├── IF 折扣率 ≤ 个人权限 → 免审通过
    ├── IF 折扣率 > 权限且 ≤ 经理权限 → 触发飞书审批
    └── IF 折扣率 > 经理权限 → 触发总监审批
```

### 3.2 处理层（实时计算引擎）

```
处理层
├── 行级计算：quantity × unitPrice - lineDiscount = lineTotal
├── 小计：Σ lineTotal = subtotal
├── 税费：subtotal × taxRate = taxAmount（按地区自动匹配税率）
├── 整单折扣：subtotal - (percentage或amount) = discountedAmount
└── 总计：discountedAmount + taxAmount = totalAmount（UI实时渲染）
```

### 3.3 输出层（多通道触发）

```
输出层
├── 文档生成：PDF.js浏览器端渲染（减少服务端成本）
├── 消息通道:
│   ├── 飞书卡片：带"查看报价"按钮的富文本消息
│   ├── 邮件：SMTP发送，PDF附件
│   └── 企业微信（预留）：小程序卡片格式
│
├── 下游触发器（状态变更→动作）:
│   ├── ON "SENT" → 创建跟进提醒（3天后）+ 计时开始
│   ├── ON "CONFIRMED" → 触发合同草稿生成 + 赢单统计
│   └── ON "REJECTED" → 创建流失分析任务（记录原因标签）
│
└── 版本固化:
    ├── 每次"发送"生成immutable版本（客户看到的不能改）
    ├── 版本链：v1 → v2 → v3（支持diff对比）
    └── 拒绝后新建版本自动继承上一版数据
```

### 5.1 状态说明

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| 草稿 | 创建后未提交的报价 | 编辑、提交、作废 |
| 待审批 | 包含超额折扣或特殊条款 | 查看、催办、撤回 |
| 审批中 | 审批流程进行中 | 查看、催办 |
| 已批准 | 审批通过但未发送 | 编辑、发送、作废 |
| 已发送 | 已发送给客户 | 查看、撤回、跟进 |
| 已确认 | 客户确认接受 | 生成合同、查看 |
| 已拒绝 | 客户拒绝 | 查看、新建版本 |
| 已作废 | 主动作废 | 仅查看 |
| 合同已签 | 已生成并签署合同 | 查看关联合同 |

## 6. 核心功能详细设计

### 6.1 新建报价流程

```
步骤1: 选择入口
├── 方式A: 报价中心 → +新建报价
├── 方式B: 客户详情页 → 新建报价（预填客户信息）
└── 方式C: 复制现有报价 → 新建版本

步骤2: 填写基础信息
├── 客户信息
│   ├── 已存在客户: 搜索选择 → 自动填充联系人
│   └── 新客户: 手工录入（客户名称、联系人、电话）
├── 报价标题: 如"2024年度网络安全服务报价"
└── 有效期: 默认30天，可修改

步骤3: 添加报价明细
├── 从产品库选择
│   ├── 搜索 SKU → 选择 → 自动填充规格/基础价
│   ├── 修改数量 → 自动命中阶梯价并计算行小计
│   └── 保存价格快照，避免后续价盘变更污染历史报价
├── 自定义产品（无库存产品）
│   ├── 手工填写产品名称、规格、单价
│   └── 系统记录为"非标产品"
├── 调整顺序: 拖拽排序
└── 实时计算: 小计 → 折扣 → 税额 → 总计

步骤4: 应用折扣（可选）
├── 行级折扣: 针对单个产品行
│   └── 如"买10送1" → 系统自动计算
├── 整单折扣
│   ├── 在权限内: 直接生效
│   └── 超额折扣: 触发审批流程
└── 折扣原因: 必填（用于审批和审计）

步骤5: 保存/提交
├── 保存草稿: 可随时修改
└── 提交: 进入审批或直接可发送
```

### 6.2 折扣审批机制

#### 6.2.1 权限矩阵

| 角色 | 标准折扣 | 额外折扣(5-10%) | 额外折扣(10-20%) | 特殊条款 |
|------|---------|-----------------|------------------|----------|
| 销售 | ≤5% 免审 | 需经理审批 | 需总监审批 | 需总监审批 |
| 销售经理 | ≤10% 免审 | 直接批准 | 需总监审批 | 需总监审批 |
| 销售总监 | ≤20% 免审 | 直接批准 | 直接批准 | 需CEO审批 |

#### 6.2.2 审批流程

```
销售申请折扣
    │
    ▼
[系统判断] 是否在个人权限内?
    │
    ├── 是 → 自动批准，状态变为"已批准"
    │
    └── 否 → 提交审批
              │
              ▼
        选择审批人（根据金额/折扣率）
              │
              ▼
        通知审批人（飞书/邮件）
              │
              ▼
        审批人决策
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
 通过      驳回      转交
    │         │         │
    ▼         ▼         ▼
  状态"已批准"  状态"草稿"  通知新审批人
  可发送客户  附带修改意见
```

#### 6.2.3 审批时效

- 普通审批：24小时内响应
- 紧急审批（标记URGENT）：4小时内响应
- 超时未审批：自动升级至上级

### 6.3 版本管理

#### 6.3.1 版本生成规则

| 触发场景 | 版本生成方式 | 原报价状态 | 新报价状态 |
|---------|-------------|-----------|-----------|
| 客户拒绝后重新报价 | 手动"新建版本" | 已拒绝 | 草稿(v2) |
| 报价过期后延期 | 手动"新建版本" | 已过期 | 草稿(v2) |
| 重大变更（>20%金额变化） | 强制要求新建版本 | 保持原状态 | 草稿(v2) |
| 审批驳回后修改 | 直接编辑原报价 | 草稿 | 草稿（不生成版本） |
| 审批通过后价格调整 | 手动"新建版本" | 已批准→已作废 | 草稿(v2) |

#### 6.3.2 版本号规则

- 基础单号：`QT-YYYYMMDD-XXXX`（如 QT-20240524-0001）
- 版本后缀：`-v{N}`（如 QT-20240524-0001-v2）
- 版本链：v1 → v2 → v3，通过 parentQuoteId 关联

#### 6.3.3 版本对比功能

- 对比维度：产品明细（增删改）、价格（单价/总价）、折扣、有效期
- 差异展示：绿色（新增）、红色（删除）、黄色（修改）
- 导出：可导出版本对比报告

### 6.4 报价发送与跟踪

#### 6.4.1 发送方式

| 方式 | 适用场景 | 确认方式 | 系统记录 |
|------|---------|---------|---------|
| 邮件发送 | 正式报价 | 邮件回执/客户口头确认 | 发送时间、收件人、附件 |
| 飞书卡片 | 快速发送 | 已读回执/点击确认 | 阅读状态、点击行为 |
| 导出PDF自送 | 线下场合 | 销售手动标记"已发送" | 导出时间、销售备注 |
| 客户门户（P2） | 在线查看 | 在线确认按钮 | 查看次数、确认时间 |

#### 6.4.2 客户确认方式

1. **邮件确认**：客户邮件回复"接受报价"（需销售手动标记）
2. **签字回传**：客户打印签字扫描回传（高正式性）
3. **口头确认**：电话/面谈确认（销售记录确认时间和内容）
4. **系统确认（P2）**：客户点击"接受报价"按钮

#### 6.4.3 跟踪提醒

- 发送后3天：提醒销售跟进客户反馈
- 发送后7天：提醒确认客户内部立项进度
- 报价到期前3天：提醒销售确认是否延期

### 6.5 报价到合同映射

#### 6.5.1 字段映射规则

| 报价字段 | 合同字段 | 映射规则 | 可修改 |
|---------|---------|---------|--------|
| customerName | partyBName | 直接复制 | 可改 |
| customerContact | partyBContact | 直接复制 | 可改 |
| items[] | contractItems[] | 产品明细→合同标的 | 可删减 |
| totalAmount | contractAmount | 直接复制 | 可改（需审批） |
| taxAmount | taxAmount | 直接复制 | 可改 |
| summary | terms.summary | 报价说明→合同摘要 | 可扩展 |
| validUntil | expectedDelivery | 报价有效期→预计交付 | 需确认 |
| - | partyAName | 从系统配置取（我方名称） | - |
| - | contractType | 默认"产品销售合同" | 可选 |

#### 6.5.2 合同草稿生成规则

1. 仅"已批准"或"已确认"状态的报价可生成合同
2. 生成后报价状态变为"合同已生成"
3. 合同草稿需补充：付款条款、违约责任、争议解决等法律条款
4. 支持多次生成（报价变更后重新生成，原合同作废）
