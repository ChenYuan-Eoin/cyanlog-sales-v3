### 2.2 核心设计原则

- **本地优先**：合同文本敏感，默认本地模型处理，不上传云端
- **工具解耦**：通过OpenAI兼容API对接任意本地模型工具（LM Studio等），不绑定特定工具
- **双轨规则**：结构化YAML规则（100%精确）+ 自然语言语义规则（灵活理解）
- **智能路由**：根据合同页数、复杂度自动选择本地/云端模型
- **双轨输出**：Word批注（给法务）+ 审核报告（给客户/销售）

### 3.2 批注生成核心实现

```python
from docx import Document
from docx.oxml import OxmlElement
from docx.oxml.ns import qn

def add_comment(paragraph, text, author="AI审核", start=0, end=None):
    """在段落指定位置添加批注"""
    if end is None:
        end = len(paragraph.text)

    # 创建批注ID
    comment_id = get_next_comment_id()

    # 创建批注内容
    comment = OxmlElement('w:comment')
    comment.set(qn('w:id'), str(comment_id))
    comment.set(qn('w:author'), author)
    comment.set(qn('w:date'), datetime.now().isoformat())

    # 批注文本段落
    comment_para = OxmlElement('w:p')
    comment_run = OxmlElement('w:r')
    comment_text = OxmlElement('w:t')
    comment_text.text = text
    comment_run.append(comment_text)
    comment_para.append(comment_run)
    comment.append(comment_para)

    # 标记原文位置
    run = paragraph.runs[0] if paragraph.runs else paragraph._p
    comment_range_start = OxmlElement('w:commentRangeStart')
    comment_range_start.set(qn('w:id'), str(comment_id))
    run.insert(0, comment_range_start)

    comment_range_end = OxmlElement('w:commentRangeEnd')
    comment_range_end.set(qn('w:id'), str(comment_id))
    run.append(comment_range_end)

    return comment_id
```

### 3.3 位置定位算法

```python
def find_text_position(doc, target_text, context=""):
    """
    在文档中定位目标文本的位置

    Args:
        doc: Document对象
        target_text: 要查找的文本
        context: 上下文文本（用于精确定位）

    Returns:
        (paragraph_index, start_char, end_char) 或 None
    """
    for para_idx, paragraph in enumerate(doc.paragraphs):
        text = paragraph.text
        if target_text in text:
            start = text.index(target_text)
            end = start + len(target_text)
            return (para_idx, start, end)

        # 如果直接找不到，尝试模糊匹配
        if context and context in text:
            # 在上下文附近查找
            start = text.index(context)
            return (para_idx, start, start + len(context))

    return None
```

### 4.2 规则引擎执行

```typescript
interface RuleResult {
  ruleId: string;
  triggered: boolean;
  extractedValue?: string;
  threshold?: string;
  comparison?: string;
  matchedCondition?: string;
  message: {
    title: string;
    description: string;
    suggestion: string;
  };
  executionTime: number;
}

// 规则执行
async function executeRule(
  rule: RuleConfig,
  contractText: string
): Promise<RuleResult> {
  const startTime = Date.now();

  // 1. 提取字段值
  const extractedValue = await extractField(
    rule.condition.field,
    contractText
  );

  // 2. 比较判断
  const triggered = compare(
    extractedValue,
    rule.condition.operator,
    rule.condition.value
  );

  // 3. 生成结果
  return {
    ruleId: rule.id,
    triggered,
    extractedValue: String(extractedValue),
    threshold: String(rule.condition.value),
    comparison: `${extractedValue} ${rule.condition.operator} ${rule.condition.value}`,
    matchedCondition: triggered ? rule.condition.operator : undefined,
    message: rule.message,
    executionTime: Date.now() - startTime,
  };
}
```

### 5.3 OCR 解析与结构化

```python
from paddleocr import PaddleOCR
import json

class ContractOCR:
    def __init__(self):
        self.ocr = PaddleOCR(use_angle_cls=True, lang='ch')

    def parse_contract(self, image_path):
        """解析合同图片，返回结构化结果"""
        result = self.ocr.ocr(image_path, cls=True)

        # 提取文本
        text_blocks = []
        for line in result[0]:
            if line:
                text_blocks.append({
                    'text': line[1][0],
                    'confidence': line[1][1],
                    'bbox': line[0]
                })

        # 结构化处理
        structured = self._structure_text(text_blocks)

        return {
            'raw_text': '\n'.join([b['text'] for b in text_blocks]),
            'structured': structured,
            'metadata': {
                'total_pages': 1,
                'total_blocks': len(text_blocks),
                'avg_confidence': sum(b['confidence'] for b in text_blocks) / len(text_blocks)
            }
        }

    def _structure_text(self, text_blocks):
        """将OCR结果结构化"""
        structured = {
            'parties': [],
            'key_terms': [],
            'payment_terms': [],
            'liability_clauses': [],
            'termination_clauses': []
        }

        # 识别甲乙双方
        for block in text_blocks:
            text = block['text']
            if '甲方' in text or '乙方' in text:
                structured['parties'].append(text)
            elif '付款' in text or '账期' in text:
                structured['payment_terms'].append(text)
            elif '违约' in text or '赔偿' in text:
                structured['liability_clauses'].append(text)

        return structured
```

## 8. 两段式 ASK 清单（2026-06-03 升级 v2 — 5 项设计决策落地）

> **详细设计**: `product-truth/feature-packets/F005-contract-ASK-upgrade.md`（开干前必读）

### 8.1 升级动机

改造前流程:

```
上传合同 → OCR → 规则 → AI → 报告 (一次出)
```

改造后流程:

```
上传合同 → OCR → 规则 → AI → ASK 清单 → 业务回应 → AI 二次判断 → 报告 (两次出)
```

核心变化: 报告前增加"业务事实采集"环节,法务用印时报告含"客户原因 / 谈判空间 / 财务意见",而非纯 AI 推断。

### 8.2 数据实体（5 张新表，v2）

| 表 | 作用 |
|----|------|
| `ask_items` | ASK 主表（条款/风险/必问/状态） |
| `ask_responses` | 业务回应（1:1 一次回答） |
| `ask_audit_logs` | 关键事件审计（who/when/what） |
| `ask_role_assignments` | 多角色分发（销售/财务/法务/技术） |
| `report_versions` | rolling 报告版本（v2 新增） |

### 8.3 状态机（单条 ASK，v2 — 3 状态）

> **v2 设计决策**: 一次回答，必填，上传人触发+澄清人入报，0 风险说明，rolling 版本。

```
PENDING (待回应，必填)
   ├─ 录入回应 → RESPONDED (触发报告升版)
   └─ 法务关闭 → CLOSED (不进报告，留痕)

RESPONDED → 不可再编辑(留痕)
   ├─ 法务重开 → PENDING(允许重新回应)
   └─ 触发新版本报告生成
```

**关键约束**（v2 5 条硬约束）：
1. **硬关单**: 生成报告前，所有 ASK 必须 RESPONDED 或 CLOSED，否则 422 拒绝
2. **一次回答**: 没有"追问"机制，回应即定稿（ask_responses 1:1）
3. **谁上传谁触发**: 触发人在 audit_log 留痕，报告中显式显示触发人姓名+角色
4. **澄清人入报**: 报告中每条 ASK 显示"responder_name (role) @ timestamp"
5. **rolling 版本**: 任何 ASK 状态变化 → 自动写入新 report_versions 行

### 8.4 API 增点（v2 — 6 个新端点 + 1 升级）

```
# v2 移除端点：
# ~~POST /api/asks/:id/ai-verdict~~       # AI 二次判断 → v2 移除
```

### 8.5 业务规则（4 条硬约束）

1. 报告生成**不强制** ASK 闭环（软提醒,标"X 项回应不足"）
2. **CLOSED 不计入报告**（法务判定不重要,不污染）
3. **CONSUMED 不可改**（已进报告的 ASK 锁定,留痕）
4. 每条 ASK **必填必要回应角色**（决定谁会被通知）

## 9. v2 变更摘要（2026-06-03 追加）

> 本节为 v2 设计决策落地后的增量说明，**v1 的 8.1~8.8 内容已被本节覆盖**。
> 完整 v2 设计见 `product-truth/feature-packets/F005-contract-ASK-upgrade.md` v2。

### 9.1 5 项设计决策（来自用户）

| # | 决策 | 用户原话 | 影响 |
|---|------|----------|------|
| 1 | 一次回答 | "预审回答一次就好了，不用反复回答" | 状态机 5 状态 → 3 状态 |
| 2 | 必填 | "必须得回答，生成必填项" | 软提醒 → 硬关单（422 PENDING_ASKS_BLOCK） |
| 3 | 上传人触发+澄清人入报 | "谁上传谁触发 ask，别人可以回答，ask 问题集会出现在报告里面，附带澄清人名字" | 报告显式含 ASK 列表+澄清人姓名+角色+时间 |
| 4 | 0 风险说明 | "无问题，就不触发，提示 0 风险?标准合同?没触发 ask 的说明" | 新增 no_ask_reason 字段，0 风险时显式说明 |
| 5 | 版本管理 | "做版本管理，围绕问题项不停更新报告" | 新增 report_versions 表，rolling 报告 |

### 9.2 v1 → v2 关键变化

| 维度 | v1（8.1~8.8） | v2（本节） |
|------|----------------|------------|
| 状态机 | PENDING/PARTIAL/RESPONDED/VERIFIED/INSUFFICIENT/CLOSED/CONSUMED（7 状态） | PENDING/RESPONDED/CLOSED（3 状态） |
| AI 二次判断 | ai-verdict 端点，反复追问 | **移除** |
| 回应表结构 | ask_responses 1:N（可多次） | ask_responses 1:1（一次回答） |
| 报告生成 | 软提醒，有 INSUFFICIENT 也生成 | **硬关单**，422 拒绝 |
| 报告内容 | 引用 ASK | **显式含** ASK 列表+澄清人 |
| 报告形态 | 单次 | rolling（report_versions 表） |
| 0 风险 | 静默 | 显式 no_ask_reason + 报告抬头说明 |
| 触发人 | 不记录 | trigger_user_id + 报告抬头显示 |
| 法务重开 | 走 transition reopen | 同 v1，触发升版 |

### 9.3 v2 数据模型增量

**新增 1 张表**:
- `report_versions`（合同 1:N，version 自增，is_current 标最新）

**改动 2 张表**:

- `ask_responses`: 新增 `responder_name`(冗余入报)、UNIQUE(ask_id) 强制 1:1

**总表数**: 4 → 5
